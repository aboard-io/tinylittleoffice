# R4-B: the Insert dialogs, local documents inside documents, the Table, footnotes, speaker notes

Read first: directive-r4-common.md, src/kit/{insert,dialog,embeds,text,note-pop,element,app,apps,page}.ts, src/apps/write/{editor,table,model}.ts, src/apps/deck/editor.ts (its Insert ▾, its ask dialog, its footnote flow, its sub-document figures), src/apps/outline/editor.ts (Insert ▾ and the document rows), src/apps/site/editor.ts (its ask dialog; the site is being redesigned by another agent: change only what the kit dialogs force), src/apps/sheet/editor.ts (its editor's public surface), docs/kernel.md §1 (fence blocks: `lang` names an app, body is its text).

Paul: "The Insert modals are badly formatted. They need to work in different kinds of docs. I should be able to include other local things on the slide, like drawings or Kanban Boards! Picture should be called Web Picture and should just be a large, well-formatted URL bar with an OK button to the right; when I enter a URL I should see a preview of the picture. From the web is also badly formatted; it should include icons for the sources that are allowed and be called Web Embed. A document by link… should be Tiny Little Office Doc. Table should be editable on insert; Open in Spreadsheet doesn't make sense; it should open as a modal with the spreadsheet in it, editable; I should be able to set the size; it should start as 3 by 3. The footnote entry tool in the Presentation Builder is very nice: port that to the Word Processor and the Outliner. Top-align the elements in the modal so they don't push down as the window expands. The speaker notes entry area needs padding."

Build in the kit, used by the Word Processor, the Presentation Builder, the Outliner and (its inserts only) the Website Builder:
1. **`<to-ask>`-style dialogs replaced by three kit dialogs** (src/kit/insert-dialogs.ts or similar, on `<to-dialog>`), each one layout: a heading, one wide 16px URL field with an **OK** button at its right (one row, the field flexes), a preview area under it, and the content top-aligned so nothing moves as the window grows:
   - **Web Picture**: a URL typed or pasted shows the picture as a preview (an `<img>` with referrerpolicy no-referrer; a broken one says so); OK inserts an `img` block (alt asked for in a second small field, optional).
   - **Web Embed**: the sources the kit's embeds.ts knows, as a row of icons with names (YouTube, Vimeo, Internet Archive, Bluesky, Mastodon, OpenStreetMap, … whichever embeds.ts supports; use lucide or the kit's own small marks, skip any you cannot draw well); a URL field; a preview card from embeds.ts; OK inserts the web block.
   - **Tiny Little Office Doc**: a field for a Tiny Little Office link (short or long); the preview is the document's first page drawn small (`view(doc, {small})` of its app); OK inserts the fence (`refFence`) with the document's text.
2. **Local documents inside a document (`<to-doc-dialog>`)**: Insert ▾ in Write, Deck and Outline lists every app ("A drawing", "A Kanban board", "A spreadsheet", …, from `apps()` minus the host) and also **Edit** on an existing document card/figure/row: a modal (native `<dialog>`, full-screen on a phone, large on desktop) hosting that app's own editor (`def.editor()` lazily, then its tag with `.value` and `docchange`), with Done writing the fence body back as one op and Cancel discarding; the host draws the result through `view(doc, {small})` as it does today. Replace every "Open in {app}" on an inline document with Edit (keep "Open in a new tab" as a second, lesser item). Undo in the host is one step per Done.
3. **Table**: Insert ▾ Table asks nothing; it puts a 3×3 table in and opens the same `<to-doc-dialog>` with the Spreadsheet editor over that table block (the fence-less case: the editor is given a one-block document of the table and Done writes the block back). The dialog's bar gets a size control (rows × columns, two small number inputs or +/- steppers) that the Spreadsheet editor already supports through its column/row commands. Write's own `<to-write-table>` grid stays for in-place typing; its "Open in Spreadsheet" becomes Edit (this dialog).
4. **Footnotes**: compare Deck's footnote flow with Write's and Outline's (they share kit/note-pop.ts; find what Deck does on top: where the note is entered, how it is placed, how the slide's foot shows it) and make Write and Outline match Deck's; every dialog's content is top-aligned (`align-items: start`, no vertical centring of the body).
5. **Speaker notes**: the notes box in Deck gets padding like the words box (12px), in both the editor and the presenting view.

Tests: DOM tests in test/browser for each dialog (layout: field+OK in one row, preview appears, OK inserts the right block; top alignment), for `<to-doc-dialog>` (opens the Drawing Tool's editor over a fence, Done writes back one op, Cancel leaves the host unchanged, Edit on an existing card), for the Table (3×3 inserted, size control adds a row), Write/Deck/Outline tests for their Insert ▾ items and Edit, Deck notes padding; a phone line in e2e/deck-phone.spec.ts (the doc dialog full-screen, OK reachable).
