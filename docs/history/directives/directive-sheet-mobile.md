# Sheets: three columns to start, and a bar that holds still on a phone

Paul: "Sheets should be three columns wide but allow me to add columns." and "Sheets nav is a mess on mobile. It bounces as I select cells and throws in multiple rows of nav."

Where things are: src/apps/sheet.ts (<to-sheet>, the bar is `class="to-toolbar sheet-bar"`), src/apps/sheet.def.ts, src/lib/formula.ts (`COLS = 6`, `ROWS = 1000`), styles.css (`.sheet-bar` rules near lines 804, 1735 and 2498 — the last one is `@media` phone: `.sheet-bar { flex-wrap: wrap }` and the formula `sl-input` takes a full row with `order: 9`; that is the "multiple rows of nav"). Paul tests on iPhone Safari (see also: inputs under 16px font zoom the page on focus; `focus()` scrolls; a sticky bar whose height changes makes the page jump).

1. **Width.** A blank sheet starts with three columns (A, B, C). `COLS` becomes the minimum drawn, 3; a document is as wide as its widest row or typed/named column, never fewer than 3. Add columns by direct manipulation: a `+` cell at the right end of the column-names row (thumb-sized on a phone) adds one column after the last; the column menu gets "Add a column after" / "Remove this column" if missing; Tab from the last cell of a row does not add a column (it moves down a row as before). Templates and existing documents keep their widths. Remove the last column only when it is empty. Charts, locks and names must follow (remapLock already handles rows; add the column case if it is not there). Update the formula reference helpers if anything assumed 6.
2. **One row of nav, always.** On every width the sheet's bar is one row that scrolls sideways with the edge fade, like every other app: delete the phone wrap rule. The formula editor leaves the bar on phones: the cell itself is the editor; selecting a cell shows its reference and raw formula in a slim fixed-height strip under the bar (`.sheet-fx`, always rendered so its height never changes, empty text when nothing is selected, tap it to edit the formula there with the keyboard). On wide screens the strip may stay in the bar as today if it does not make the bar wrap; prefer the same strip everywhere if that is simpler (one mechanism).
3. **No bouncing.** Find and fix each cause with a real phone-sized check: (a) every cell `input` and the formula strip ≥ 16px font on phones (or `font-size: max(16px, …)`), so Safari does not zoom; (b) `focus({ preventScroll: true })` on cell focus, then scroll only the table's own scroll box so the cell is visible, never the page; (c) the bar's DOM must not change size when the selection changes — tools that appear only with a selection (Lock/Unlock, column tools, chart pick) keep their place and go `disabled` instead of vanishing, and `aria-pressed` toggles do not change width; (d) sticky header/corner cells are sticky within the table's scroll container, not the document; (e) no re-render of the bar's `sl-select`s on each keystroke (check `updateComplete` churn; keep selection state out of what the bar renders where possible). Verify with a single targeted Playwright run at an iPhone viewport (390×844, `isMobile: true`, `hasTouch: true`, WebKit if installed, else Chromium with the device descriptor): tap ten different cells, assert `document.scrollingElement.scrollTop` stays 0 and the bar's `offsetHeight` never changes and is ≤ 56px, and the bar is one row (`scrollWidth` may exceed `clientWidth`). Take before/after screenshots for the report.
4. Tests: DOM tests for the three-column default, `+` adds a column, remove only when empty, names/locks follow; the Playwright assertion above as a new spec in e2e (it is part of the phone checks, not the deploy gate — see how other phone specs are tagged).
5. Docs: README sheet row and docs/tlo.md (a sheet is as wide as its rows; agents may write any width); skill template if it says six columns; `npm run skill`.

Pacing rules as usual; one targeted Playwright spec at a time, never the suite.
