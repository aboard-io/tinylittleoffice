# R4-E: the Word Processor: page breaks, joining a heading, the pasted space

Read first: directive-r4-common.md, src/kit/{text,textops,clipboard}.ts, src/doc/{tlo,model}.ts (the `hr` block: "a break: the next slide, page or card"), src/apps/write/{editor,model,view,def}.ts and tests, test/browser/text.test.ts.

Paul: "Let me insert page breaks in the word processor docs. If I hit delete and pull text that is formatted as a title header up one line, that text loses its formatting and the empty space below is still set to title header font. If I cut and paste a sentence that has a space at the end the space is removed when I paste."

1. **Page breaks**: Insert ▾ in the Word Processor gets **Page break** (and Mod+Enter? no: Mod+Shift+Enter is free in Write; bind it and say so in docs/editing.md §8), which puts an `hr` block at the caret (the kernel's break). In the editor it is a card drawn as a thin dashed rule with the words "Page break" small in its middle (not a menu-opening card: a tap selects it, Delete/Backspace removes it as any card; `text-embed` need not fire). `view()` starts a new page at every `hr`; print/PDF, the HTML export and .docx page-break there (docx: `<w:br w:type="page"/>`; .md keeps `---`; .rtf `\page`). Test each.
2. **Joining into or out of a heading**: find the exact cause of the symptom and fix it in textops.ts with the standard's rule: when a join (Backspace at the start of a block, or Delete at the end of the block before) meets an **empty** block, the empty block goes and the block with words keeps its kind and its element (Docs' behaviour: words never lose their heading by being pulled up into an empty line); when both have words, the block before keeps its kind (as now). Then check the DOM: after the op exactly one element remains for the joined block and nothing styled as the heading is left (look at `inherit()` in text.ts: a kept key on the wrong block would leave a stale `<h1>`; prove it with a DOM test of `p(empty)` + `h1 Title`, caret at the end of the empty paragraph, Delete → one `<h1>` "Title", caret at its start; and the mirror with Backspace at the start of the heading → the same).
3. **The pasted space**: the kit's own copy (`copyData`: TLO text plus marked HTML) is read back by `pasteFrom` through `parse(text)`, and the parser drops a line's trailing spaces as Markdown does, so "a sentence " loses its space. Fix: when the clipboard carries our marker, read the runs from the HTML (`htmlToBlocks`, which keeps the spaces) for an inline fragment, and keep `parse(text)` for whole blocks; or carry the fragment's runs in the HTML explicitly. Trailing and leading spaces of a copied fragment must survive a paste inside words. Test: copy "sentence " (with the space) from the middle of a paragraph, paste it elsewhere, the space is there; a whole-paragraph copy still pastes as a block.

Tests in test/browser/text.test.ts and src/apps/write/tests; node tests for the exports' page break. PW_PORT=4405 (only if an e2e line is needed; a DOM test is enough here).
