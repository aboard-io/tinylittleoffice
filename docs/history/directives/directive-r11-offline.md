# R11-offline — the copy of the app on the device is gone

**Paul, 2026-10-10:** *"Let's remove the 'save app on this device'."* The switch in the hamburger that reads "Keep the app on this device", and everything that exists only for it.

## What goes

- The switch (`src/kit/drawer.ts`, the `to-switch` with `offline.on`), its state and its line (`src/kit/offline.ts`: `OfflineStatus`, `onOffline`, `offlineOn`, `offlineSupported`, `offlineState`, `dropOffline`, `setOffline`, `keepOffline`; the `tinyoffice.offline` key in `kit/store.ts`'s comments and in `kit/privacy.ts`, where Private forgets it and `forgetOffline` and the `offline` field of what the device holds). `siteRoot`, `canInstall`, `install` and `installByHand` (Add to home screen) stay: move them to a file named for what they are if `offline.ts` would be left holding only them, and update every import.
- The service worker: `src/sw.ts`, its entry in `vite.config.ts` (`sw` in `input`, the `sw.js` name in `entryFileNames`, the `__TLO_VERSION__` stamp and `dist/files.json` with its hash, the plugin that writes them), `scripts/check-build.ts`'s sw and files.json checks, `test/offline-files.test.ts`, `test/check-build.test.ts`'s parts about them, `test/verify-deploy.test.ts`'s likewise, `test/browser/offline.test.ts`. `public/_headers` loses any header that was for `sw.js`. `main.ts` no longer calls `keepOffline`; its header no longer says so.
- The words: every language's `'Keep the app on this device'` and the status lines (`offline.line`: saving, ready, updated, failed, off), the Private/Saved switch's line where it names "the offline copy", `kit/network.ts`'s row that says the switch stops the files being asked for (the network doc, `docs/network.md`, regenerated by `npm run docs:network`), and `npm run i18n:check` clean with no gaps and no orphan (a key in a language file that en.ts no longer has fails the check; take them out).
- The docs that name it: README.md, CONTRIBUTING.md, docs/threat-model.md, docs/transparency.md, docs/translation.md, docs/gap-analysis.md (one line each, or the paragraph where it is the subject), docs/dependencies.md through its script if `scripts/dependencies.json` mentions it, the skill (`npm run skill`) if its words do.
- `manifest.webmanifest` stays (Add to home screen is not this), and so does the Private/Saved switch.

## Proof

- A browser test that the drawer has no such switch and that nothing registers a service worker (`navigator.serviceWorker.getRegistrations()` is empty after the shell mounts, in a test that would have found one before).
- `npm run build` green; `scripts/check-build.ts` green with its sw checks gone; the chunk sizes before and after in the report (main should shrink: say by how much), budgets.json lowered to follow.
- `grep -rn "offline\|sw\.js\|files\.json" src scripts test docs public README.md CONTRIBUTING.md` in the report, with each remaining hit explained (a `navigator.onLine` or a "works offline" that is about the link, not this feature, may stay).

## Not this

- Nothing about Private/Saved, the pictures switch, the theme, the size, the language or Add to home screen changes.
- No "coming back later" comment anywhere.
