# R6-icons: an icon in rich text is drawn as the icon; the icon picker offers emoji too

Read first: directive-r6-common.md, src/kit/icons.ts (LIBRARY is the starter set a document may name; the rest of Lucide joins through addIcons only once the picker's lazy chunk has loaded), src/kit/icons-picker.ts (chooseIcon: the dialog, searchIcons, iconCategories), src/kit/icons-search.ts, src/kit/icons-meta.ts (generated from Lucide's tags), scripts/icons.ts (how that is generated), src/kit/text.ts renderRuns (an icon run is `<span class="ic" data-icon=name>` with nothing inside), src/styles/text.css (`.ic::before { content: ':' attr(data-icon) ':' }` — this is why Paul saw the text `:car-front:` and not a car), src/apps/write/editor.ts insertIcon, the places a view skips an icon it does not know (`iconNamed(x) ?` in src/apps/deck/view.ts, src/apps/site/view.ts, src/apps/draw/view.ts, src/kit/notes.ts if any).

Paul (2026-10-10): "An icon inserted in the Word Processor showed as the text `:car-front:` and not the icon." And: "Native emoji as a set of options in the icon menu popup."

Build:
1. **The editor draws the icon.** An icon run is drawn as the icon's SVG inside the chip (kit/icons.ts `icon(node)` or the inner markup; keep the chip atomic, contenteditable=false, role=img with the name as its label, sized to the line's cap height, inheriting currentColor). The `:name:` text is never shown for a name the library knows. A name outside the starter set loads the full set once (the same lazy chunk the picker uses — split it so the names and nodes can load without the dialog's code if that is cheap; otherwise the picker chunk is fine) and the editor draws again when it arrives; until then, and for a name no library has, the chip shows the name in small type, not `:name:`. Document the rule in icons.ts's header: *a document may name any Lucide icon; the starter set draws at once, the rest after one lazy load.*
2. **The views draw it too.** Deck, Site, Write (view.ts), Outline, Board and every other view that draws an icon by name must not silently skip a name outside the starter set: the shell's view path and the exports (kit/exports.ts: print, PDF, PNG, HTML, the site's export) await the full set when a document names an icon the starter set lacks (one helper in icons.ts: `ensureIcons(names: Iterable<string>): Promise<void>`, resolving at once when every name is known; a pure `iconNames(doc)` in src/doc or icons.ts lists what a document names). A view itself stays synchronous; it is the caller that awaits first.
3. **Emoji in the picker.** The icon picker gets a second set beside Lucide: **Emoji**, the native characters, searchable by name and keyword, in Unicode's groups (Smileys & Emotion, People & Body, Animals & Nature, Food & Drink, Travel & Places, Activities, Objects, Symbols, Flags). Native API first: there is no browser API that lists emoji by name, so the names come from the CLDR annotations (the npm package `cldr-annotations-full`, file `annotations/en/annotations.json`: each emoji's `default` keywords and `tts` name), generated by a script (scripts/emoji.ts, like scripts/icons.ts) into src/kit/emoji-data.ts: a compact table of [character, name, keywords, group], base emoji only (no skin-tone or hair variants: the OS keyboard does those), flags included; checked in; loaded lazily with the picker, never in the first chunk. No runtime dependency. Say in docs/dependencies.md (or its generator) where the data is from and its licence (Unicode).
   The picker: a two-way switch at the top (Icons · Emoji) or the sets as sections of one scroll with the search spanning both — choose what reads best at 390px and say why. Picking an emoji resolves `chooseIcon` with the character itself; the callers that put the result into words (Write, Deck, Outline, Site) insert the character as text (an emoji is words, not an icon run); callers that need an icon *name* (a shape's icon in Draw, a slide's glyph) are told through an option (`emoji: false`) and do not see the Emoji set. The characters are drawn by the system font, never by a web font.
4. The `:car-front:` case is a test: a document `:car-front:` opened in the Word Processor draws an SVG chip, not text; a name outside the starter set is drawn after the lazy load; an unknown name shows its name in small type and writes back unchanged (byte-stable).

Tests: a browser test for 1 (both a starter icon and a full-set one; the chip's SVG is in the DOM; copying the chip still carries `data-icon`); a node test for `ensureIcons`/`iconNames`; a node test over the generated emoji table (no duplicate characters, every entry has a name, each group non-empty, every character is a fully-qualified emoji); a browser test that the picker's search "car" finds both the Lucide car and 🚗, and that picking the emoji returns the character.
