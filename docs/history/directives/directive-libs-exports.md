# Libraries by the deep-domain rule, and the export formats

Paul's words: "consider our export formats, global usage ... follow your rule above". The rule: take a dependency where the domain is deep and not ours (fonts in PDFs, units, layout, colour); keep hand-rolled code where the format is the product (the TLO text grammar in src/lib/tlo.ts, the sheet formula engine in src/lib/formula.ts, richtext). Every dependency: MIT/BSD/ISC, pinned exact version in package.json, loaded as a lazy chunk only when the feature is used (as Leaflet is), no network at runtime, must work under the strict CSP in public/_headers (no eval/new Function, no inline script). Keep the main bundle from growing: check `npm run build` chunk sizes before and after and report them.

Do, committing a WIP after each:

1. **PDF text for the world.** src/kit/textpdf.ts + pdf.ts write raw PDFs with only the 14 standard fonts, so anything outside Western Latin (Cyrillic, Greek, Arabic, Hebrew, CJK, Devanagari) cannot be exported, and accents outside WinAnsi are dropped. Fix in two layers: (a) For Write and the other page/print apps whose PDF is text (letter, invoice, contract, programme, zine/booklet if they are HTML pages), prefer the browser's own print-to-PDF: a `Print / Save as PDF` action that opens the document in a print view with `@page { size: A4|letter; margin: … }` honouring Write's `paper:` setting and clean print CSS (no bar, no chrome, page breaks that keep headings with their first line), so the browser's text engine and fonts do the work in every script. (b) For the drawn PDFs (diagrams, sheets, deck, timeline, charts) keep our writer but embed a real font with pdf-lib + @pdf-lib/fontkit, lazily: subset the IBM Plex Sans we already ship (Latin, Cyrillic, Greek) and fall back to the standard font only when embedding fails. Measure text with the embedded font's metrics. If pdf-lib proves too heavy or awkward for (b), keep the writer and instead make (a) available for drawn things too (print the SVG), and say so. Test: a unit test that a PDF with "Привет, κόσμε, ñandú" round-trips its text (pdf-lib can read back), and a DOM test that the print view carries the paper size.

2. **Sankey with d3-sankey** (+ d3-shape for the link paths) in src/lib/chart.ts: replace the hand layout with d3-sankey's node ordering and link positions; keep the chart's API, the SVG output contract the tests assert, and the pure (no DOM) nature. Both modules are tiny and tree-shake; import only what is used.

3. **Themes in OKLCH with culori**: the website/Quick Links THEMES in src/lib/sitemodel.ts and the board's stage shades and the deck themes pick shades by hand. Use culori (tree-shaken: oklch, formatHex, interpolate only) to derive a theme's shades (background tints, hover, border, dark variant) from its one or two base colours so every theme has consistent contrast in light and dark. Contrast: check every theme's text-on-background is at least WCAG AA (4.5:1) with a unit test over THEMES (culori has wcagContrast). Do not change the list of theme names.

4. **Calculator units and conversions with mathjs**, lazily: in src/lib/calc.ts keep the tape, the modes and the names (`a = 12`), but evaluate expressions with a custom mathjs instance built with `create({ ...only the needed dependencies })` so units ("3 inch to cm", "60 mph in km/h", "2 cups + 3 tbsp"), big numbers, factorial, trig, logs and `derivative`/`simplify` work; the mathjs chunk must load only when Calculator opens. Make sure mathjs does not use eval under the CSP (it compiles to closures; verify with a DOM test under happy-dom and by grepping its code for `new Function`). The calculator must still work for the plain arithmetic tape exactly as the tests expect, and a unit test proves units convert. If the custom build still exceeds ~120 kB gzipped, report the number and keep it anyway unless it also slows the first open badly.

5. **Export formats audit.** List every export each app offers today (grep download/pdfOf/… in src/apps/*.def.ts and src/kit/browser.ts) in a table in docs/exports.md: app × format (PDF, PNG, SVG, .xlsx, .csv, .ics, .geojson, .html, .md, .txt, .gif, .json) and what each file contains. Then fill the gaps that matter for "global usage" and for a document people hand on: (a) Write gets .docx (a minimal, valid WordprocessingML writer over fflate: paragraphs, headings, bold/italic/underline/strike, lists, links, images by URL omitted; about 150–250 lines; test by unzipping and checking document.xml, and that LibreOffice-style validation passes structurally) and .md; (b) Sheet gets .csv with the locale's separator honoured (`;` where the decimal comma is used) and .xlsx keeps formulas (already done for names; check dates and money); (c) Calendar/Gantt/Todo .ics with proper UTF-8 and line folding (RFC 5545) — verify with a unit test on a multi-byte title; (d) every text export is UTF-8 with BOM only where Excel needs it (CSV), never elsewhere. Every export's file name comes from the document title, transliterated/safe for all filesystems.

6. Docs: README (exports, calculator units, PDF) and skill/tinyoffice/SKILL.tpl.md (what agents can promise about exports and the calculator's units syntax), `npm run skill`.

Report chunk sizes before/after, every dependency added with version and license, what was deliberately not done.
