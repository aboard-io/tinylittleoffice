# R6-urls: no hyphen in a generated link, so a pasted link never breaks across a line

Read first: directive-r6-common.md, src/kit/codec.ts (B64, toBase64Url/fromBase64Url, the y/z/r/E shapes), src/kit/route.ts (parseHash/routeHash and what characters a payload may hold), src/kit/short.ts (short links and their codes), src/kit/crypt.ts, src/kit/envelope.ts, src/kit/sign.ts (signatures and keys written into links and envelopes), src/kit/compare.ts, src/kit/embeds.ts and src/kit/insert-dialogs.ts (where they test for our own links), tinier/tinier.ts and tinier/page.html (the short-link page reads links on its own), src/api.ts and the media worker if they validate a payload, scripts/make-cards.ts, the corpus the tests read, docs/kernel.md, docs/crypto/*.md, README.md, skill/tinyoffice/SKILL.tpl.md and public/llms.txt (regenerated by `npm run skill`), and every regex matching `[A-Za-z0-9_-]` (`grep -rn "A-Za-z0-9_-\|A-Za-z0-9-_" src scripts tinier docs skill`).

Paul (2026-10-10): "Can we get rid of dashes in generated URLs? They linebreak arbitrarily when pasted anywhere."

Why: base64url's alphabet ends in `-` and `_`. A hyphen is a line-break opportunity in every text renderer (UAX #14 class HY), so a long payload full of them wraps wherever a mail client, a chat or a document feels like it, and the link is cut. An underscore is not (class AL). Of the characters a URL fragment may hold unencoded (RFC 3986: unreserved and sub-delims and `:@/?`), `~` is unreserved, never percent-encoded by a browser, not a break opportunity, and not special to any linkifier we know; `.` is cut from a link's end by linkifiers and `!`, `*`, `'` and `)` are mangled by Markdown and chat apps.

Build:
1. The alphabet's 63rd character is `~` where it was `-`: `ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789~_`. Every link, envelope, short-link payload, signature, key fingerprint and QR code we write uses it. Reading is lenient: `-` decodes as 62 too (one entry in the reverse table, one sentence in the header), so every link already made, the corpus, the templates and the tests' fixtures still open. Nothing else is kept for the old form; nothing is written with `-` any more (search for a hand-written hyphen in a link literal: templates, the tour, docs, the skill).
2. Every validator that admits a payload admits `~` and still admits `-`: route.ts, short.ts, tinier, api.ts, the worker, compare.ts, the "is this one of our links" tests in embeds.ts and insert-dialogs.ts and clipboard.ts's linkToFence, and the skill's own description of a link (SKILL.tpl.md, llms.txt: regenerate and read what they say about the encoding; say it in one line).
3. The QR code: `~` in byte mode is unchanged; a test that a link with `~` scans back (kit/qr.ts's tests, if they decode) or at least encodes without widening the code's version for the same byte length.
4. Short-link codes (short.ts): if their own alphabet holds a hyphen, the same rule applies to codes made from now on; say what the code alphabet is in the report.
5. docs/kernel.md's and docs/crypto/*'s description of the encoding say `~`; README likewise. The crypto docs carry test vectors (docs/crypto/*.md, test/crypto-vectors.test.ts): a vector's bytes do not change, only its text form, so update the vectors' text and keep the bytes, and say so in the commit.

Tests: codec round trips with every byte value (the 62nd and 63rd characters appear and are `~` and `_`); a legacy string with `-` decodes to the same bytes; a link written by encodeDoc holds no `-` for a document of random bytes; routeHash/parseHash accept both; tinier's own tests; the vectors.
