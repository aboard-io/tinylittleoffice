# R18-agent-fast: an agent told "go to tinylittleoffice.com and do something" is working in one fetch

**Paul, 2026-10-11:** *"Do LLMs have a complete understanding of this system as quickly as possible when told 'go to tinylittleoffice.com and do something'? Speed is so important and LLMs can be so slow."* Measured on 2026-10-11: an agent that fetches the home page gets a `<noscript>` of two sentences and no pointer to anything; `/llms.txt` is 56 KB (about 14,000 tokens), the whole skill, so the first useful thing is a long way down. An agent needs the shape of a link and one working example within its first thousand tokens.

## The design

- **Two files.** `/llms.txt` becomes short (under 6 KB): what it is in two sentences, the link shape, the API import line (`import { link, read, lint } from 'https://tinylittleoffice.com/api.js'`), one complete example per app in one line each (the smallest document that shows the shape), the three rules an agent breaks first (the two-space link rule, a title slide alone, commas in a list), and the line 'The whole description: /llms-full.txt'. `/llms-full.txt` is today's file. Both written by `scripts/make-skill.ts` from the one template, so they cannot drift; the skill's SKILL.md stays the full one.
- **The home page points the way for a fetcher.** `index.html` gets `<link rel="alternate" type="text/plain" href="/llms.txt" title="For agents">` and the `<noscript>` gains one line: 'Agents: https://tinylittleoffice.com/llms.txt says how to make a document as a link.' The site's `_headers` serves `/llms.txt` as `text/plain; charset=utf-8` with a short cache. Also `/.well-known/llms.txt` → the same file (a copy in the build), since some agents look there.
- **The API answers fast.** `api.js` stays an entry of its own with no app code in it (check the chunk: `apps()` and `templates()` lazy); a test holds `api.js` under 25 KB gzipped so an import is one small fetch.
- **Examples on demand** (Paul, 2026-10-11: *"Would it make sense to have a command that produces examples for LLMs so they can explore the document model ad hoc?"*). Three commands in the CLI and the same three in the API: `tinyoffice shapes <app>` lists the shapes the app reads (a heading, a task list, a money column, a Venn, a title slide, …), one line each with the shape's name and what it is for; `tinyoffice example <app> [shape]` prints the smallest document that shows the shape, then its JSON (r18-json), then what `lint` and `measure` say of it, for one shape or all of the app's; `tinyoffice try <app> <file|->` is the loop in one call: lint, measure and the JSON of a draft. The examples are generated, never hand-written: `scripts/make-skill.ts` cuts the smallest instance of each shape from the app's templates and the kernel's fixtures into `packages/doc/examples/<app>.json`, checked in and regenerated by the test. Every example lints clean, round-trips `write(parse(x)) === x`, and its JSON fits the schema. The short llms.txt names the three in its first screen.
- **Two kinds of agent, two doors** (Paul, 2026-10-11: *"Will LLMs be able to download and run Tiny Little Office locally, like Claude's normal chat? Or should you point to JSON with that data and a guide to extracting the relevant sections?"*).
  - *An agent that can only fetch and write* (a chat with a web tool, no shell) never needs to run anything: the plain link form (`https://tinylittleoffice.com/<app>/#doc=<percent-encoded TLO>`) is a document made with nothing but percent-encoding, so llms.txt puts that form first and the API second. It fetches only what it needs: llms.txt is an index that links one short file per app, `/llms/<app>.txt` (under 4 KB each: the app's shapes, one example, its rules), and the examples of this directive are also static files on the site, `/examples/<app>.json` (the same `packages/doc/examples/<app>.json`, copied into the build), so 'show me a sheet with a money column' is one small fetch. No lint for this agent: a lint endpoint would mean a document reaching our server, which the threat model forbids; llms.txt says to keep documents short and to prefer the shapes shown.
  - *An agent with a runtime* (a sandbox, a shell, Deno, Bun, Node) downloads the CLI: `packages/doc` is published to npm as `tinylittleoffice` (not private; `npx tinylittleoffice lint …`; no dependencies; Node 24 as it is, `.ts` run directly as the CLI does today, so there is no build step and the package is the source), with its README the agent's quick start; api.js stays importable by URL in Deno and Bun, and the npm package is the Node path (the review found the URL import fails in Node). The deploy publishes it (Paul, 2026-10-11: *"Can you publish it to npm and make that part of deploy"*): `scripts/deploy.mjs` gains a step 'the command line' after the Workers: in `packages/doc`, if `package.json`'s version differs from `npm view tinylittleoffice version`, run `npm publish --access public --provenance=false` with `NPM_TOKEN` read from the checkout's `.env` (gitignored; never in the repo or a log) and passed as `NODE_AUTH_TOKEN` to npm through a `.npmrc` line written to a temp dir, not to the home directory; with no token the step says so and the deploy goes on (the site does not wait for npm). The package: `"name": "tinylittleoffice"`, `"private"` removed, `"version"` the site's version (scripts/version.ts), `"files"` the CLI, the examples, the schema and the README, `"repository"`, `"homepage"`, `"bin": { "tinylittleoffice": "tinyoffice.ts", "tinyoffice": "tinyoffice.ts" }`; `src/api.ts` and what it imports must be reachable from the package or bundled into it by a build step that writes `packages/doc/dist/api.js` (one file, no dependencies) which the CLI imports: say in the report which, and hold it by a test that installs the packed tarball into a temp dir and runs `tinylittleoffice lint` on an example. `docs/self-host.md` and the README's agents paragraph name `npx tinylittleoffice`.
- **A measure in the tests.** `test/llms.test.ts`: `/llms.txt` under 6 KB, contains the API line and one example per app, each example lints clean through `lint()`; a count of tokens by a simple 4-characters-a-token estimate under 1,500 for the part above the first `##`.
- docs/transparency.md or the README's agents paragraph names both files.

## Proof

- The tests above; `npm run skill` writes both files, the per-app files and the examples; `scripts/check-build.ts` sees both files in dist; a test runs `example` for every app and shape and holds each clean.

## Not this

- No content negotiation at `/` (serving text to non-browsers): a stranger's `curl` of the home page gets the HTML and its pointer.
