# R9-grammar: the format written down once, and everything fuzzed from it

Read first: directive-r9-common.md, docs/kernel.md (the format and the operation set), src/doc/tlo.ts in full (the parser and writer, `write(parse(x)) === x`, splitAttrs, guardEnd, the escaping), src/doc/ops.ts (every op and its inverse), src/doc/table.ts, formula.ts, src/kit/clipboard.ts (htmlToBlocks, the paste path), src/kit/codec.ts (packDoc, the DICTIONARY, the three encodings), the existing property and fuzz tests (grep `fuzz\|property\|fc\.` in test/ and src/doc/tests), fast-check (R9-walks adds it; share the dev dependency).

Why: the byte-stability fuzz test caught a real ambiguity on the URL round. One generator of documents from the grammar fuzzes the parser, the writer, the operations, paste and the codec together.

Build:
1. **The grammar.** `src/doc/grammar.ts` (or `docs/tlo.ebnf` with a tiny reader): TLO's blocks, runs, marks, attributes, tables, fences, footnotes, the head, written formally once; a generator (`arbitraryDoc`) from it with fast-check, biased to the hard cases (marks at block edges, attributes that look like words, `\{`, `~~` beside links, empty cells, nested lists at depth, icons and emoji in names, right-to-left words). The parser is not rewritten; the grammar documents it, and a divergence found is a bug in one or the other, decided by docs/kernel.md and reported.
2. **The properties** (node tests, each a `fc.assert` with the shrunk counterexample in its message): write(parse(x)) is x for every generated document; parse(write(d)) is d for every generated model; every op applied then its inverse gives the document back, and apply(ops) then apply(inverse(ops)) over a random sequence; `pages()` of a document never throws and never gives zero pages; a pasted document read as HTML (htmlOf → htmlToBlocks) written again reads the same; the formula engine: a + b = b + a, (a + b) + c = a + (b + c) within float tolerance, a reference to a cell equals the cell's value, a cycle is reported and never loops; packDoc then decode is identity over generated documents and the chosen encoding is never longer than the raw.
3. **The dictionary, measured.** A script (`scripts/dictionary.ts`, dev only) that trains a deflate dictionary (the zlib/fflate way: the most common substrings of the templates and a corpus of generated documents) and reports, for each template and for Paul's 1,908-character document (docs/directives/r6-perf-payload.txt is not in the repo; use the templates and the generated corpus), the link length under today's DICTIONARY and under the trained one. The report says the numbers; the dictionary is changed only if every template is shorter or equal and the largest wins by 5% or more, with the vectors of docs/crypto and the fixtures regenerated by their scripts and old links still reading (the codec reads `y` with the dictionary it was written with: say how a second dictionary is told apart, a version letter, before changing anything).
4. docs/kernel.md gains the grammar's place and the properties' list.

Tests: the properties of point 2 (fast, 200 runs each by default, 2,000 under `npm run fuzz`); the dictionary script's report in the builder's `done`.
