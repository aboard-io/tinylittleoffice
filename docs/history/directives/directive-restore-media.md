# RS-6: the media proxy at media.tinylittleoffice.com, and the picture policy

Read first: directive-restore-common.md, docs/transparency.md, tinier/ (the shortener worker: its wrangler config, how it is deployed and tested, its no-logging stance), src/kit/{embeds,text,link-guard,privacy}.ts and the R4-H branch's picture gating (landed on next: "Show pictures from the web"), public/_headers (CSP), src/kit/page.ts, the e2e smoke.

Paul (2026-10-09): "Maybe we have a media whitelist server and make a media.tinylittleoffice.com subdomain where we can put images; figure out where else you can whitelist safely." Decided with him: a proxy and cache, not uploads; every web picture goes through it so the reader is never revealed; a whitelist of hosts whose pictures show at once; every other host asks first.

Build:
1. **The Worker** `media/` (sibling of `tinier/`, same tooling, deployed by the same `npm run deploy` with its own wrangler config and the subdomain): `GET /img?u=<url>`: the address must be https, the host on the whitelist or not (both proxied; the whitelist only matters in the kit); fetch with `redirect: follow` (max 3, same rules), no referrer, no cookies, a 10 s timeout; require `Content-Type: image/*` (svg allowed only as `image/svg+xml` served with a sandboxing CSP: `default-src 'none'; style-src 'unsafe-inline'`), cap at 5 MB (streamed, cut off past the cap), cache at the edge (`caches.default`, 7 days, keyed by the address, `Vary` none), respond with `Content-Type`, `Cache-Control: public, max-age=604800, immutable`, `Content-Security-Policy: default-src 'none'`, `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: cross-origin`, no cookies, no other headers from the origin; rate limit per client with the Workers rate-limit binding or a KV counter (120/min); errors as small text with the right status (400, 404, 413, 415, 502); `OPTIONS` for CORS from the site's origin only; **logs nothing** (no `console.log` of addresses; say so in the header comment). Node tests with a fetch stub for each rule; a wrangler dev run in the e2e is not required.
2. **The whitelist** in the kit (`src/kit/media.ts`): hosts whose pictures show at once: `upload.wikimedia.org`, `commons.wikimedia.org`, `archive.org` and `*.archive.org`, `images.unsplash.com`, `images.pexels.com`, `live.staticflickr.com`, `raw.githubusercontent.com`, `user-images.githubusercontent.com`, `*.githubusercontent.com`, and `media.tinylittleoffice.com` itself; documented in docs/network.md with the reason for each (static, public, licensed content; no per-reader tracking since the proxy fetches). A function `pictureSrc(url)` returns the proxied address for any https picture; `data:` and `blob:` pass through.
3. **The policy in the kit**: every `<img>` the site draws from a web address uses `pictureSrc` (the editors, the views in the browser, previews, the display mode, the Website Builder's frame); a whitelisted host shows at once; any other host keeps the R4-H gate ("Show pictures from the web", naming the host) and the author's-session rule; exports embed the picture bytes fetched through the proxy (so a PDF or PNG never calls the origin from the reader either). Self-hosters: `VITE_MEDIA_URL` sets the proxy base; empty means pictures load directly with the gate for every host.
4. **CSP**: `img-src 'self' data: blob: https://media.tinylittleoffice.com` (the generic `https:` goes); the network test from docs/transparency.md item 1, if present, lists the media host; else add the host to the CSP generation and leave a note for that task.
5. **Docs**: docs/transparency.md (the media section under §1), docs/threat-model.md if it exists (the picture row), README's privacy paragraph, docs/network.md (the whitelist with reasons; what else is allowed and why: embeds tap-to-load in sandboxed frames, map tiles and place search only when the map is shown or a search is tapped and never proxied by OSM's policy, fonts self-hosted, nothing else).

Tests: node for the Worker's rules and for `pictureSrc`/the whitelist; DOM for a whitelisted picture showing at once through the proxy address and a non-whitelisted one gated; the CSP header test. PW_PORT=4424.
