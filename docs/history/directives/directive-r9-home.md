# R9-home: a way back to the home page, and a word before an unsaved document is left

Read first: directive-r9-common.md, src/kit/chrome.ts as R9-chrome left it (the header: the app's icon link `.to-here` that opens a new document of the app, the title, the burger), src/kit/shell.ts (`changed`, `fresh`, `arrived`, how a document arrives and when `changed` is set; the route change on hashchange), src/kit/store.ts and library.ts (`keeping()`, what Saved keeps), src/kit/drawer.ts (the "This document" section: Share…, Download), src/kit/dialog.ts (`<to-dialog>`), src/kit/share.ts (`copyText`), test/browser/chrome.test.ts, shell.test.ts, drawer.test.ts, docs/editing.md's chrome paragraph.

Paul, 2026-10-10: "I need a way to get back to the home state. Maybe the top left icon could do that. But if I've entered data it should tell me that I need to copy the link if I don't want to lose data. Think about it." The drawer's brand link was the way home until its head became the language picker; nothing is now.

Build:
1. **The top-left icon goes home.** The header's app icon is a link to `#/` (aria-label and title: t('Home')), in every app and state. "New {noun}" moves to the drawer's "This document" section as its first row (icon: the app's; label: t('New {noun}')), above Share… and Download; the keys it had (if any) keep working.
2. **A word before an unsaved document is left.** When the icon is tapped (or the drawer's Home, if R9-chrome gave it one) and the document lives nowhere but its link, the shell asks once in a `<to-dialog>` before going: that is, when `!keeping()` (Private) and the document has changed since it was opened or begun (`changed`), and nothing else: under Saved the library has it, and an unchanged document is already in the link that brought it. The dialog's words: heading t('This document lives in its link'), one line t('Nothing is saved on this device. Copy the link to keep it, or keep it on this device; Back brings it too.'), three buttons: t('Copy the link and go') (copyText(the current link, flushed), then home), t('Keep on this device and go') (setKeeping(true), the keep, then home), t('Go without'); Escape and the close stay. The dialog is `to-chrome`'s (or the shell's, whichever owns the route), one element, used by every way of leaving the shell offers (the icon, the drawer's rows that open another app or template, a hand-off in the Download table), not by the browser's Back.
3. **Closing the tab** in that same state (Private, changed) registers `beforeunload` with `preventDefault()` so the browser shows its own leave warning; removed again when the state no longer holds (kept, or unchanged, or the link copied through Share). Never under Saved.
4. docs/editing.md says where Home is and when the question is asked; the strings join en.ts and, through `npm run i18n:gaps`, the nine languages in their voice (the translators' glossaries: documento/enlace, document/lien, …).

Tests (browser): the icon's href is `#/` and its label Home in Write and in Draw; "New {noun}" is the drawer's first document row and opens a blank document; under Private with a changed document the icon opens the dialog and the hash does not change; Copy the link and go puts the link on the clipboard (stubbed) and goes home; Keep on this device and go turns keeping on, keeps the document and goes home; Go without goes home; Escape stays; under Saved, or with nothing changed, the icon goes home at once; a `beforeunload` listener exists exactly in the Private-and-changed state (dispatch a cancelable `beforeunload` and check `defaultPrevented`). i18n:check green with every language.
