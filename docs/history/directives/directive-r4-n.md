# R4-N: a document opens with the focus in the logical place

Read first: directive-r4-common.md, docs/editing.md, src/kit/shell.ts (how an editor is mounted, the title box, display mode), src/kit/element.ts, every src/apps/*/editor.ts (each has a focus helper of its own: focusRow, focusBox, focusCell, focusCanvas…) and tests, test/browser/shell.test.ts, the phone e2e specs (no page scroll on focus; the 16px rule).

Paul (2026-10-10): "When I open a new doc put the focus on a logical place when possible. First cell, header, etc."

Build: when an editor is first shown (a new document from the home page, the hamburger, a template, or an existing link, but not in display mode and not when the document is locked), the focus goes, without scrolling the page, to the place a person would start: the Word Processor: the caret at the end of the last block of a new document, at the start of the first for an opened one? No: always at the start of the first words block (a new document is empty: its one paragraph); the Spreadsheet: A1 selected (the cell focused, text selected as a keyboard move does); the Presentation Builder: the first slide's headline; the Outliner: the first row's words; the To-Do List: the first task; the Kanban Board: the first stage's first card's words, else the stage's name; the Calculator: the entry line; the Drawing Tool: the canvas (the select tool, nothing chosen); the Animator: the stage; the Diagram Maker: the picture (the first thing focusable, not editing); the Calendar: today's day cell (or the first day of the shown month); the Trip Planner: the first stop's name, else the map; the Website Builder: the site's name in the page (inside the frame) else the first thing. A template opens the same way. The shell never leaves the focus on the title box or the body. On a phone the focus is set the same way (iOS will not raise the keyboard without a tap, which is fine: the caret is there when it does). Write the rule into docs/editing.md §1 ("A document opens with the focus where a person starts: …", listing each app's place) and add `focusFirst()` to the AppDef editor contract in docs/kernel.md (DocElement gets a `focusFirst()` hook the shell calls after the first draw; each editor implements it with its own helper).

Tests: one DOM test per app in its editor tests ("opens with the focus in …"; `document.activeElement` and, for words, the caret position), a shell test that the title box does not take the focus and that display/locked modes do not focus the editor, and the phone e2e checks (scrollTop stays 0 on open for every app in one loop).
