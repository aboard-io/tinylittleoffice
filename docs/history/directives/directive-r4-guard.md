# R4-H: the link guard, and pictures from the web asked for first

Read first: directive-r4-common.md, the old tree's /home/exedev/workspace/tinyoffice/src/widgets/link-guard.ts (read-only reference: port its `leaving()`, the guard dialog and the capture-phase click catcher; Shoelace is gone, use the kit's `<to-dialog>`), src/kit/{shell,dialog,embeds,text,privacy,store,route}.ts, src/styles/kit.css, src/apps/outline/editor.ts (document/web rows), src/apps/deck/editor.ts (sub-document figures), src/apps/site/view.ts (the generated page is the person's own site: no guard there), public/_headers (CSP), test/browser/shell.test.ts.

Paul: "When I click on links everywhere on this site I am supposed to see a modal with a big warning and the site name to help me avoid getting scammed." And on hosted images, agreed with him: a web picture is a tracking pixel for whoever reads the document, so readers are asked before pictures load.

1. **The link guard** (`src/kit/link-guard.ts`, installed once by the shell): a capture-phase click/auxclick catcher on the document; a link that leaves this origin opens a `<to-dialog>` saying in large type that you are leaving Tiny Little Office, the host name big, the full address under it (wrapped, selectable), a red **Cancel** as the default (focused) and a green **Go** (opens in a new tab with `noopener noreferrer`); a link whose protocol is not http(s), mailto or tel does not open at all (a toast says so). Same-origin links, the site's own downloads (blob:) and the app's internal routes pass. It covers every app, the display mode, the Outliner's and Deck's "Open in a new tab", the link bubble's Open, the embeds' "open on the site" links, and the Website Builder's editor (not the generated site itself). Mod+click and middle click are caught too. Keyboard: Enter on a link goes through the same dialog. Strings in the kit section.
2. **Pictures asked for first**: an `img` block from another origin is drawn, in every editor and view that shows it in the browser (the Word Processor, Deck, the Outliner's rows, the Website Builder's frame, the display mode), as a quiet card: the picture's host name, its alt, and **Show pictures from the web** which shows every web picture of this document for this visit (state in memory per document hash; under Saved, a per-device "always show pictures" switch in the hamburger's Privacy group, off by default). The author's own session shows them without asking: a picture inserted in this session (the shell marks the hash of a document it edited) is shown. Exports (PDF, PNG, HTML, docx) include pictures as now: the person exporting chose to. Data: and blob: pictures always show. `referrerpolicy="no-referrer"` everywhere an `<img>` is drawn (grep and fix). Say in the About/privacy text why.
3. Docs: README's privacy paragraph and docs/rebuild.md note both.

4. **Previews for the documents under each app** (Paul: "When you list documents under apps, show them with previews"): each kept document's row on the home page (src/kit/home.ts; the R4-A branch is turning the home page into rows: start from what next has when you begin, and keep its shape) shows a small preview at its left, drawn from the kept hash (`decodeDoc` → `parse` → the app's `view(doc, { small: true })`, the first page as an inline SVG, about 56px tall, the page's own aspect), drawn lazily as rows scroll into view (IntersectionObserver) and kept in a small in-memory cache by hash, so a long list costs nothing until it is seen; a document whose text no longer reads shows a blank page. The hamburger's document results get the same preview. The same web-picture rule applies inside previews (a web picture in a preview is a grey box, never fetched). Tests: a kept Word Processor document's row holds an SVG preview once visible; the cache draws it once.
