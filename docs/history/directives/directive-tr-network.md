Read first: directive-r4-common.md (the contract), docs/transparency.md §1 items 1 and 7 (the brief; Paul's words there), docs/network.md (hand-written today: the rules, the picture whitelist with a reason per host, what else the site may ask), scripts/headers.ts (mediaSource; the CSP written into public/_headers from VITE_MEDIA_URL), test/csp.test.ts, src/kit/media.ts and pictures.ts (the proxy, the whitelist), src/kit/embeds.ts (Bluesky, Wikipedia…), src/apps/trip (OpenStreetMap tiles and place search), src/kit/short.ts (tinier), src/kit/icons.ts (the lazy chunk), src/kit/drawer.ts (About), vite.config.ts, public/, scripts/offline-files.ts.

Build:
1. `src/kit/network.ts`: the one registry of every host the site can reach: `{ host, what (one line), when ('after a tap' | 'while shown' | 'never until a switch' | 'on share'), carries (what the request holds), stops (the switch or action that prevents it), by (the module) }`, with a short header comment. Every module that reaches the web imports its host from here (no literal host elsewhere in src: a test enforces it). The picture whitelist stays in pictures.ts but its hosts are entries here too.
2. `scripts/network-doc.ts` writes `docs/network.md` from the registry (the hand-written rules and reasons kept as prose sections the script carries; the table generated; a header "generated from src/kit/network.ts, do not edit") and `public/network.html`, a plain static page (no JS, the site's base styles inline, dark mode) served at /network and linked from About ("What leaves your browser") and the README; `npm run docs:network` runs it; `npm run build` runs it first; a test fails when the committed docs/network.md is stale.
3. The CSP: scripts/headers.ts takes connect-src, img-src and frame-src from the registry (by a `csp: 'connect' | 'img' | 'frame'` field) plus the site itself; test/csp.test.ts asserts every registry host is in the right directive and nothing else is. Keep the current behaviour for the media host from VITE_MEDIA_URL.
4. `test/network.test.ts`: builds are not run in tests, so it greps `src/` (and the Worker folders tinier/ and media/) for `https?://` hosts and fails on any host that is not in the registry, not localhost, and not inside a comment or a template's sample document (templates hold example URLs: list the template files as exempt and say why); and asserts no analytics, error-reporting, font-CDN or tag-manager host appears anywhere (a short deny-list: google-analytics, googletagmanager, sentry, segment, plausible, fonts.googleapis, fonts.gstatic, hotjar, mixpanel, cloudflareinsights…). Item 7 of the brief is this test plus one sentence in About.
5. docs/transparency.md: mark items 1 and 7 built with the date and the file names.
