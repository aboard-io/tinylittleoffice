# Fixing an app after the editing audit — the common contract

The tree: /home/exedev/workspace/tinyoffice-next, branch next (your worktree is a branch off it; see your prompt). Binding, in this order: docs/editing.md (the standard: read it whole, §8 last), your app's audit at <scratchpad>/audit/<app>.json (every finding: path, way, status, detail, file, line, severity, fix), the kit as it is on your branch: src/kit/text.ts (events: text-ops, text-select, text-enter {shift}, text-exit {dir}, text-selectall, text-escape, text-embed), src/kit/context.ts (`<to-context>`), src/kit/rows.ts (row selection: the one implementation for apps with rows — read its header), src/kit/element.ts (DocElement: `edit(ops, key)`, `undone(entry)`, `undoTools()`), src/kit/bar.ts (`tool`, `btn`, keep:true), src/kit/clipboard.ts (copyData/docToHtml/pasteFrom/htmlToBlocks, the generator marker).

What to do:
1. Go through every finding in your audit whose status is `missing`, `differs` or `unknown`. For each: if docs/editing.md §8 says the behaviour is deliberate for your app, leave it and list it under "kept"; if `unknown`, settle it with a DOM test and fix it if it fails; otherwise fix it as the standard says (the audit's `fix` is a hint, the standard is the law). `works` findings are not touched, but must stay green.
2. The standard's cross-app rules that apply to every app: the bar ends with `${this.undoTools()}` (remove any Undo/Redo tools of your own); key handlers never act when the event's target is a bar button, a field, a dialog, a popover or words being edited (guard on the target); `undone(entry)` restores the selection/caret of the thing the entry's first op touched; selected things get `<to-context>` in the standard's order (§5 for canvases, §6 for rows); row apps use `src/kit/rows.ts` rather than their own range code; drags are pointer events with `touch-action: none` on the handle only; 44px hit areas under `(pointer: coarse)`; `touch-action: manipulation` on editing surfaces; every bar button that acts on an editor's selection is `keep: true`; copy/cut/paste of a thing write TLO text plus `docToHtml` with the marker and read both.
3. Tests: one DOM test per fixed path in src/apps/<app>/tests/editor.test.ts (real events: beforeinput for what the editor owns, keydown for shortcuts, ClipboardEvent with a DataTransfer, PointerEvent for taps and drags); a node test for each new pure command in model.ts; a phone line in e2e/<app>*.spec.ts for touch findings (WebKit, iPhone 14), run with `PW_PORT=<your port> npx playwright test e2e/<file> --workers=1`.
4. Checks before finishing, one at a time, never in the background (a 2-core box shared with another agent): `npx tsc --noEmit -p .`, `npm run i18n:extract` then `npm run i18n:check` (new strings in your app's section of src/i18n/en.ts; reuse keys that exist), `npx vitest run src/apps/<app> test/browser/text.test.ts`, then `npx vitest run` whole once at the end (if a file times out under load, rerun that file alone before calling it a failure).
5. Commit WIP early and often; finish with one real commit on your branch in the house voice (sentences: what changed and why). Do not merge or push. Do not touch other apps' folders. Kit changes only if a kit bug blocks a fix: minimal, tested in test/browser, and named in the report.

Report (structured): branch, commit, worktree, fixed (one line per finding path), kept (path + the §8 line that allows it), tests (exact counts), kitFiles, left (anything not done, and why), ok (true only when every check in step 4 is green).
