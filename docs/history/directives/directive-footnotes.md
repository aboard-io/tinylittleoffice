# Footnotes in rich text

Paul: "Rich text should allow footnotes. They should display at the end of a doc or at the bottom of a slide."

Rich text is src/lib/richtext.ts (runs and blocks over TLO/Markdown in src/lib/tlo.ts), edited in Write (src/apps/write.ts, contenteditable), an outline's items (src/apps/outline.ts), a slide's words (deck), the print apps, and shared text tools. One mechanism, native first.

1. **Grammar.** A footnote is written inline where its mark sits: `^[the note's words]` (Pandoc's inline footnote; the note travels with its sentence, nothing to keep in sync, numbering is by order of appearance when drawn). Also *read* Markdown's reference form, `[^id]` in the text with `[^id]: the note` as a paragraph anywhere, since documents are Markdown and agents write it; on write, keep the form the document used (a Run gets `fn?: string` for the note's words; a block-level definition is folded into the run on read and written back as `[^n]: …` paragraphs at the end if the document came that way — or simplify to always writing inline if the round-trip tests allow; say which). A note's words are rich text themselves (inline marks and links allowed, no blocks). Document it in the richtext.ts header comment and in docs/tlo.md.
2. **Drawing.** The mark is a superscript number (`<sup><a href="#fn-3" id="fnref-3">3</a></sup>`, `role="doc-noteref"`). The notes: in Write and in a printed/PDF page and in the HTML export, a `<section role="doc-endnotes">` at the end of the document — a thin rule, small type, each `<li id="fn-3">` with a return link ↩ (`role="doc-backlink"`); on a Deck slide, at the bottom of that slide in small type (the notes a slide holds, numbered from 1 on each slide; when presenting too); in Outline's "View as" document view, at the end of the document; in Markdown export, write `[^n]` with the definitions at the end (portability); in .docx (if the other agent's writer has landed by the time you merge, else skip and say so) real Word footnotes are deep — write them as endnotes paragraphs at the end. Printing: `@media print` keeps the notes with the end of the text, and a footnote mark never splits from its word.
3. **Editing in Write.** A `Footnote` tool in the one bar's text tools (icon: Lucide `Superscript`... check UI keys; add one) inserts `^[]` at the caret as a superscript chip and opens its editor; the chip is a `contenteditable=false` element inside the text carrying the note as `data-fn`; tapping a chip opens a small native `popover` anchored to it (the Popover API, not a dialog) with a one-line rich-text field for the note's words and a Remove; Escape closes and returns focus to the chip. Backspace over a chip removes the whole note. Copy/paste within Write keeps it (the serializer writes `^[…]`). Outline items and slide words use the same richtext editing path where they share it; where an outline item is a plain input, the `^[…]` text form simply works and is drawn in View as.
4. **Phone**: the popover fits a phone width and sits above the keyboard (Paul tests on iPhone Safari; the Popover API is in Safari 17+; fall back to a `<dialog>` where `popover` is unsupported).
5. **Tests.** Unit: parse/write round-trips for inline and reference forms, numbering order, a note with a link and italics inside, notes split per slide, Markdown export form, HTML roles and ids unique when two documents are on one page (a deck embedding a write: prefix ids). DOM: insert via the bar, edit via the popover, Backspace removes, the end-of-document section updates live, a slide shows its notes at its foot.
6. Docs: README (Write/rich text), docs/tlo.md (grammar), skill/tinyoffice/SKILL.tpl.md (agents: `^[note]` works in any rich text; shows at the end of a Write document or the foot of a slide), `npm run skill`.
