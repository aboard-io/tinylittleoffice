# Living short links (phase 9, pulled forward — Paul: "Build the living short links")

Binding: docs/rebuild.md ("Living short links"). Port the shortener from the old tree (tinier/: tinier.ts, worker.ts, page.html, schema.sql, wrangler.jsonc, test/tinier.test.ts) and the client (old src/lib/short.ts, limits.ts) into the new tree, then add ownership. Native crypto only (Web Crypto); no library.

Today: POST /api {c, iv, ttl} → {id, exp}; GET /api/<id> → {c, iv}; the page decrypts with the key in the fragment and goes to the long link; rows expire; a brake per address; MAX_BYTES 8 KiB; CORS to the site.

Add:
1. **Owner key.** At creation the client makes `o` (32 random bytes) beside the AES key; the request carries `owner: sha256(o)` (base64url) and the server stores it (`owner TEXT`, plus `ver INTEGER NOT NULL DEFAULT 1`, `updated INTEGER`). `PUT /api/<id>` with `{c, iv, ttl?, o}`: the server hashes `o`, compares in constant time to the stored hash, and replaces `c`, `iv`, bumps `ver`, sets `updated`, extends `exp` when `ttl` is given; 404 when unknown or expired, 403 when the proof fails (same body and timing for both, to leak nothing). `DELETE /api/<id>` with `{o}` forgets the row. GET /api/<id> also returns `ver` and `updated`. The brake covers PUT and DELETE. Rows without an owner (none will exist in the new world; keep the column nullable anyway) cannot be updated.
2. **Links.** Public: `https://tinier.tinylittleoffice.com/<id>#<key>` as today — it always opens the latest version, because the AES key never changes across updates (only the IV and ciphertext do). Owner: `…/<id>#<key>.<o>` — what the author keeps. The page strips `.<o>` and, after decrypting, sends the browser to the long link with the ownership attached in the hash query the shell defines (`#/v1/<app>/<payload>?s=<id>&o=<o>`); coordinate the exact shape with the shell's router in src/kit (read it; if it has no query part yet, add `?s=&o=` parsing there in a minimal way and say so).
3. **Client** (`src/kit/short.ts`): `shorten(link, seconds)` → `{ short, owner, expires }`; `update(id, o, link, seconds?)`; `forget(id, o)`; `unshorten`; `EXPIRIES` gains `A year` (365 days; add to TTLS). `limits.ts` ported (room meter).
4. **Shell**: in the Share panel (coordinate with the skeleton's share code), when the document was opened from an owner link (`s` and `o` present) and has changed, show "Update the short link" (one tap; toast "Updated · version 3"), "Extend" (the expiry choices) and "Forget this link"; when a short link is made, show both links with the owner one marked "Keep this one to update it later", and offer to keep it in the device's own list (the Drive/"my links" store the skeleton has, if any; else localStorage under the privacy setting's rules — not when Private). The document's own `key`/`sig` head fields are unrelated; leave them.
5. **Size**: MAX_BYTES 16 KiB (Paul: lift to 16k); the page's and the client's limits agree; the room meter knows a short link's own length.
6. **Security notes in code and docs**: the server sees only ciphertext, an owner hash, and timing; it cannot read, cannot tell versions apart, cannot forge an update. `o` never appears in a public link, a log or a request body except the PUT/DELETE that proves it (over TLS). Rate-limit PUT like POST. No enumeration: ids are random, 404 and 403 identical.
