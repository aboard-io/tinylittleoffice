# R4-F: the Website Builder, edited in the page

Read first: directive-r4-common.md, src/apps/site/* (model, view with the frame page and its EDIT script, editor, templates, tests), src/kit/page.ts (the generated page with hashed scripts; the CSP), src/kit/{dialog,context,text,insert}.ts, docs/kernel.md §8 decision 3 (sections edited beside the frame: Paul has overridden it), docs/editing.md §6/§8, e2e/site.spec.ts.

Paul: "Site builder: I expect to add objects from a contextual insert menu on the top left, and to be able to remove them too. I don't have an edit view to the right. I simply edit each object with its own mini form. For instance if it's a big link it pops up with text (rich text) and a URL. I can move things up and down and left and right as makes sense. I can directly edit everything. I need a preview function for the site builder. I should never edit Markdown as a human."

Build:
1. **No side panel.** The editor is the page itself, full width, in the sandboxed frame as now (the document is still the kernel's; every edit is ops). Each object in the page (a page, a section, a heading, a paragraph, a button, a big link/card, a small link, a picture, an embedded document, the shop's products table) is tappable; a tap opens its **mini form** as a kit `<to-dialog>` anchored near it (or a `<to-context>` for the quick actions): the form holds exactly that object's fields: words as a `<to-text>` (rich where the object is rich; one line where it is one line), a URL field where there is one, an icon picker where an icon fits, a picture's address and alt, a section's look. Done writes one op (or a few) and closes; Escape discards. Nothing is ever typed as `Label | url` or with markers.
2. **Insert at the top left**: a contextual Insert ▾ (the kit's `<to-insert>`) at the top left of the frame (fixed as the page scrolls) listing what can go in at the current place: Page, Section, Heading, Paragraph, Button, Big link, Small link, Web Picture, Web Embed, Tiny Little Office Doc, Products (those dialogs come from the kit if the R4-B branch has landed on next when you start; if `src/kit/insert-dialogs.ts` is absent, use the site's own ask dialog for now and say so). A new object is made after the object in hand (or at the end of the section) and opens its mini form at once.
3. **Remove and move**: every object's quick actions (in its `<to-context>`): Edit, Move up, Move down, Move left / Move right where the object sits in a row (small links, cards, buttons), Duplicate, Delete, in the standard's §6 order. Keys from the standard act on the object in hand (Delete, Mod+D, Alt+arrows, Mod+Alt+Left/Right).
4. **Preview**: a **Preview** tool in the bar shows the page as a visitor sees it (the same frame with the editing script off, full width, no handles), with one **Edit** button to come back; Escape returns. Also the Display Link (if the R4-A branch has landed: route flag `?d`) lands on this preview.
5. Update docs/kernel.md §8 decision 3 and docs/editing.md §8's Website line (words are edited in the page, in each object's form). Keep the generated page's CSP: scripts hashed, no inline handlers; the editing script may grow but stays one hashed script.

Tests: DOM tests for each object's form (open by tap, fields, Done writes, Escape discards), Insert at the top left making each kind and opening its form, the quick actions and keys, Preview on and off, byte-stable documents; the phone e2e (390px: the forms inside the screen above the keyboard, Insert reachable, Preview).
