# R19-social-cards: a shared document previews as itself

**Paul, 2026-10-11:** *"What would it take to make social share actually preview the document? Esp Bluesky."* and *"Don't limit it to short links. When we explicitly share with a social network from in the app, that's when we do this. Perhaps we add an id as a ? param. Otherwise it's generic per app with gray shapes indicating the app content."*

Today no link previews as its document: the document is after the `#`, which no crawler sends, and the shortener holds it sealed. A preview needs a readable picture on a server, so it exists only when a person asks the app to share with a network, and it rides along as a query parameter the document never touches: `https://tinylittleoffice.com/write?c=k8hwicw#/v1/write/…` and `https://tinier.tinylittleoffice.com/k8hwicw?c=m3q9tzx#…`. Without `?c=`, a link previews as its app's generic card, redrawn as gray shapes.

## The design

**The card.** When a network button in the Share dialog (`src/kit/share-dialog.ts`: Bluesky, Mastodon, X, LinkedIn) or the device's share sheet (`shareNative`) is pressed, and the dialog's 'with a preview' switch is on (on by default; the choice kept in `store`), the app draws the document's first page through the app's own `view()` and `kit/raster.ts` into a PNG of 1200 by 630: the page letterboxed on a neutral ground at the largest size that fits, the way `scripts/make-cards.ts` composes the app cards now (share the composing code; the script and the dialog draw the same shape). The title is the document's (`ctx.title` or the app's `title(doc)`); the text is the first 200 characters of the document's plain words, or the app's line when there are none. Drawn once per document state (keyed by the link's text, in memory) so pressing two networks uploads one card. Email gets no card and neither does Copy link: a preview is for a network's feed, where the person has chosen to show the document.

**Where it lives.** `POST https://tinylittleoffice.com/card` with the PNG bytes, the title, the text and the app id (multipart or JSON with base64; the builder picks and says why); limits: the PNG at most 400 KB, the title 120 characters, the text 300; the daily brake of r17-shortener counts a card as a request (the brake code moves to `tinier/brake.ts`, imported by both Workers, with the site Worker's own `BRAKE_KEY` secret set once by hand). A card is immutable, has a random id of the shortener's shape, and expires after a month, the short link's longest life (Paul, 2026-10-11: "Keep it for a month"): a network fetches the card once, when the post is made, and keeps its own copy, and a month covers a link pasted again later. It is stored in the shortener's D1 database in a `cards` table (`tinier/migrations/0002-cards.sql`: id, app, title, text, png BLOB, exp), bound by both Workers, and the hourly sweep deletes expired cards with expired links. The shortener's header keeps its sentence that it never sees a link: a card is not a link, and the privacy page says plainly that a card is readable on the server by the person's own choice.

**The site Worker.** The site is static assets today (`wrangler.jsonc` has no `main`). It gains `site/worker.ts` with `run_worker_first` for the app pages and `/card/*` only (everything else stays assets): `GET /card/<id>.png` serves the picture (`Cache-Control: public, max-age=31536000, immutable`; 404 for an unknown or expired id); an app page or `/` with `?c=<id>` is the built page with its head's tags replaced: `og:title`, `og:description`, `og:image` (`/card/<id>.png`), `og:image:width`, `og:image:height`, `og:image:alt` (the title), `twitter:card` `summary_large_image`, `twitter:title`, `twitter:description`, `twitter:image`. Plain string substitution over the tags the build writes (a test asserts each appears exactly once in the built HTML, so the substitution cannot miss), not HTMLRewriter, so the Worker's logic runs under node tests like tinier's does. An unknown id serves the page unchanged. The page with `?c=` is cacheable for an hour. Both go through the edge: the Worker answers from `caches.default` when it can and puts what it reads from D1 there (the PNG for the card's life, the page for an hour), so a card is read from the database once however many fetchers come (Paul, 2026-10-11: "cache it, this is Cloudflare"). The picture itself is still drawn by the person's browser at share time: a Worker has no rasterizer, networks refuse SVG previews, and the browser already draws the page exactly as the person sees it. The shortener's `GET /<id>?c=<card>` landing page does the same with the same code (one module, `tinier/cards.ts`, used by both Workers).

**The link.** The shared link is the one the dialog shares today (the long link, or the short link when the network's limit in `kit/limits.ts` says the long one does not fit), with `?c=<id>` before the `#`. The shell ignores `location.search` for routing (check it; a test), and on load strips the query from the address with `history.replaceState` so a link copied afterwards carries no stale card. If the upload fails (offline, the brake, the limit), the share goes ahead without a card and a toast says 'Shared without a preview' with the reason.

**The generic cards.** `scripts/make-cards.ts` keeps composing each app's card from its first template's first page, but greeked: every `<text>` in the page's SVG becomes a rounded gray bar of the text's measured width and height (Chromium measures it; the script already runs under Playwright), every fill and stroke becomes one of two grays, pictures become gray boxes; the icon and the app's name stay in ink. The card then says what kind of document it is without a word of anyone's. The home card stays the mark. Regenerate the cards.

**The dialog.** A switch 'Show a preview of the first page' at the top of the networks section, on by default, with one sentence under it: 'A picture of the first page and the title are kept readable on our server for a month so the network can fetch them. The document itself is not.' In every language (American English; the others by `npm run i18n:extract` and translation in each language's voice). `docs/privacy.md` and the Privacy dialog's page gain the paragraph; `docs/network.md` regenerated with the `/card` entry in `src/kit/network.ts`.

**Robots.** The SEO directive marks the shortener noindex: that is a header and a meta tag, never a robots.txt disallow of the ids, or X's and Facebook's fetchers will not read the card. Check both Workers' robots files say `Allow: /`.

## Proof

- `test/cards.test.ts` (unit): the Worker's `handle` with a fake store: POST stores and returns an id and exp; over the limits is 400 with the sentence; the brake refuses the 101st; GET of the PNG with the headers; an app page with `?c=` carries the tags with the title escaped; an unknown id serves the page unchanged; the shortener's landing page with `?c=` likewise; expired cards are swept; a card a month old is gone.
- The built HTML test: each replaced tag appears exactly once in `dist/index.html` and every app page.
- `test/browser/share.test.ts`: pressing Bluesky with the switch on uploads one card (a stubbed fetch), opens the intent with a link carrying `?c=`; pressing X then uploads nothing more; with the switch off, no upload and no `?c=`; Copy link never uploads; a failed upload shares without `?c=` and says so.
- `test/browser/shell.test.ts`: a link with `?c=` opens its document and the address loses the query.
- `e2e/`: through the dev Workers (`wrangler dev` for both; the site Worker's dev in `package.json`), a POST then a fetch of the page with `?c=` returns the tags and the PNG decodes at 1200 by 630.
- The cards test: every app's generic card has no `<text>` but the name, and the greeked bars are where the template's words were (compare counts).
- After deploy, Paul pastes a shared link into Bluesky's composer: the card shows the page. (Bluesky's card fetcher is public but the dev box is not reachable from it; the live site is the test.)

## Not this

- No card for Copy link, for email, for the API or the CLI. No preview of a document nobody shared with a network.
- No change to the sealed link or the shortener's link rows. No image hosting beyond the card.
