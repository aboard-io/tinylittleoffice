# RS-1: the privacy layer: password, signing, the signed state, keys, envelope, what the device holds

Rows: docs/gap-analysis.md "Privacy, signing, contract" except the Contract row (RS-2 does that after you). Old tree: src/lib/crypt.ts, sign.ts, envelope.ts, privacy.ts, widgets around the header's privacy button, the Privacy dialog, their tests. New tree: src/kit/{privacy,store,codec,route,shell,share,drawer,dialog,links,short}.ts, src/doc/model.ts (head: created, by, key, sig), the Share dialog as the R4-I branch left it (one dialog; put the new items where they belong in it), docs/kernel.md §1.

Build:
1. **Password protection**: port crypt.ts (WebCrypto: PBKDF2 → AES-GCM; keep its parameters and vectors in a node test). A sealed document travels as its own payload form in the route (codec/route learn the sealed shape; a sealed link opens an unlock dialog: the password field 16px, a wrong password says so, Escape leaves the document closed with its title hidden). Share dialog gets **Password…** (set, change, remove; the document is re-sealed on every change while a password is set, so the address bar and short links always hold ciphertext); the header shows a lock state (see 3). Under Saved, the password is never stored; the unlocked document stays unlocked for the visit.
2. **Signing**: port sign.ts (Ed25519 with the P-256 fallback), the key kept through store.ts (made on first use under Saved; under Private a key lives for the visit and the dialog says so). The envelope: `created` (minute-rounded, set when a document is first written), `by` (the signer's name, asked once and kept), `key` (the public key) and `sig` over the signed message as envelope.ts defined it (port the message exactly so old signed documents verify). **Sign** in the Share dialog signs the current text; any change after a signature makes it stale (the state shows it) until re-signed; **Verify** is automatic on open.
3. **The signed state in the header**: a state pill beside the title: unsigned (quiet), signed by {name} (green, the key's fingerprint on hover/tap), signature does not match (red), locked (a lock); tapping opens the Privacy dialog. Dark-mode tokens, contrast-tested, 44px.
4. **Key management** in the Privacy dialog: the fingerprint, Export key (a file, and a copyable text), Import key, Forget key (with a confirm that says signed documents will no longer verify as yours); the dialog also lists **what this device holds** (preferences, the offline copy, the library's count, kept short links, the key) with Forget-all, and **Download everything** as one zip (the kit's zip.ts) of every kept document as .tlo plus the key file if asked.
5. Created time and By shown in the Share dialog's head line ("Created 9 Oct 2026, 14:03 · by Paul").
6. Docs: README's privacy section, docs/kernel.md §1 (the envelope), the About text.

Tests: node tests for crypt (vectors), sign (sign/verify, tamper fails, fallback), envelope (message, minute rounding, old-tree fixture verifies); DOM tests for the unlock dialog, Password set/remove and re-seal on change (the route holds ciphertext), Sign then verify, stale after an edit, the header pill's four states, key export/import/forget, what-the-device-holds and the zip (contents listed). Phone e2e line: the unlock dialog inside 390px. PW_PORT=4420.
