# Languages, part one: the checks that make a translation safe to merge

Read first: directive-r4-common.md (the contract), src/kit/i18n.ts (t(), plural(), languages(), browserLanguage, directionOf, register), src/i18n/en.ts's header and sections, scripts/i18n-extract.ts (what --check verifies today: keys used vs defined, placeholders in every language file), test/i18n.test.ts, the language chooser in the drawer (grep "languages()" in src/kit), docs/rebuild.md's phase that mentions translations.

Nine language files are about to be written by other agents (es, fr, de, pt-br, it, nl, ja, zh-hans, ar), each a copy of en.ts with the right-hand sides in that language. Build what makes such a file safe to merge, and nothing that changes a string:

1. `npm run i18n:check` also verifies, for every language file: the key set equals en.ts's (missing keys and extra keys each listed by name; missing is a failure, since English would show through); every placeholder of the key appears exactly once in the value; every plural `{n|…}` has exactly as many forms as `new Intl.PluralRules(code).resolvedOptions().pluralCategories` has (so fr has three: one, many, other; ja one; ar six; pl four), and `#` appears in at least one form; no value is byte-identical to its key unless the key is a proper noun, a symbol or a single word the language shares (list the allowed ones in a small set in the script, and print the rest as warnings, not failures); the file has no `// New — sort me` section. `npm run i18n:gaps -- <code>` prints the keys a language lacks, one per line with the English, so a later pass can fill only those.
2. A node test that loads each language file through `register()` and renders t() for every key with representative vars (each placeholder as its name, n as 0, 1, 2, 5, 21) without throwing, and that `languages()` lists them and `languageName()` names each in itself.
3. A browser test that chooses each language from the drawer, loads it (the lazy chunk), and checks: the `lang` and `dir` attributes on `<html>` follow it (ar is rtl), the home page, the Word Processor's bar and the Share dialog draw without an English fallback (count fallbacks: add a dev-only hook in i18n.ts that records keys missed in the language in use, cleared on each test), and at 390px the bar does not wrap and the drawer's items do not overflow their width (German and French are a third longer than English: report any string that overflows by name so the translator can shorten it).
4. A length rule for translators, written into en.ts's header in two sentences: a string on the bar or in a menu may be at most a third longer than the English, a button's label the same length or shorter; everything else free.

Tests: the ones above. Commit on your branch; do not translate anything.
