# R6-paste: a paste brings only what the editor can hold, and keeps lists, headings, marks and links from anywhere

Read first: directive-r6-common.md and rule 1 of directive-r4-common.md (a person never sees or types a marker), src/kit/clipboard.ts in full (copyData, docToHtml, carriedRuns, htmlToBlocks, pasteFrom, fitBlocks, linkToFence), src/kit/text.ts paste() and the marks-only rule, src/apps/write/editor.ts pasteAfter/pasteIn, src/doc/tlo.ts (what the writer escapes in plain words: `^[` is; check `**`, `*`, `++`, `~~`, `==`, `:name:`, `[words](address)`, `- ` and `1. ` at a line's start, `#`, `>`, `|`), test/clipboard.test.ts, docs/editing.md §Paste ("A paste never brings styles the document cannot keep").

Paul (2026-10-10): "Paste into rich text must never bring syntax the UX does not natively support (no raw Markdown, HTML remnants, TLO markers)." And: "Pasted bullet points came in flat: paste should keep lists (and headings, bold/italic, links) from HTML and from Markdown-looking plain text, in the Word Processor and any host that has blocks."

Build:
1. **Fixtures from the real world, first.** Add test fixtures of what the clipboard actually carries, as text/html and text/plain pairs, from: Google Docs (a list is `<ul><li dir="ltr"><p dir="ltr"><span style="font-weight:700">…` — a `<p>` inside the `<li>`; `<b style="font-weight:normal">` wrapping everything), Microsoft Word (`<p class=MsoListParagraph>` with `<span style='mso-list:Ignore'>·<span>&nbsp;</span></span>` bullets and `<o:p>`), Apple Notes and Mail (`<ul class="Apple-…"><li>`, `<div><br></div>` blank lines, `-webkit-text-stroke` styles), Notion (`<ul><li>` beside `<div>`s), Slack and a browser page (nested `<div>`s, `<span>` styles, `<a>`), and plain text alone: "• one\n• two", "- one\n- two", "* one", "1. one\n2. two", "1) one", tab- or space-indented nested bullets, a single bullet line with no newline, a heading written `# Title`, and `**bold**` on one line. Each becomes a test that says what blocks come back. The suspect for "flat bullets": htmlToBlocks closes the item when a block tag opens inside an `<li>` (`<p>` in Docs' list items), so the item becomes a paragraph; and a lone line is never read as TLO (`text.includes('\n')`), so a single pasted bullet is words.
2. **Lists, headings, marks and links survive.** From HTML: a block tag inside an `<li>` stays that item's words (with a `<br>`/line break between inner paragraphs); nested lists keep depth; `<ol>` keeps its numbers; Word's and Notes' bullet glyphs are read as items and the glyph dropped; headings by tag and by Docs' role/style where the tag is a `<p>` with a heading style; bold/italic/underline/strike/highlight by tag and by style (font-weight ≥ 600, font-style italic, text-decoration, background-color on a span); links by `<a href>` (http(s), mailto, tel only). From plain text: one line is read as TLO inline too (a lone "• one" is an item; `**bold**` on one line is bold); the bullet glyphs `•`, `◦`, `▪`, `–`, `—` at a line's start are items as `-` is.
3. **Nothing unsupported arrives.** After reading, the pasted blocks are fitted to what the host can hold (fitBlocks per shape, and the host's own vocabulary: a `line` takes words; `lines` takes items and paragraphs; a `doc` takes the kernel's blocks — but an `edge`, a `fence` of an app the host has no card for, and an `img` where pictures are not shown become words; a table pasted into a host that cannot draw one becomes its rows as paragraphs of tab-separated words); HTML remnants (`<o:p>`, `<!--StartFragment-->`, `<meta>`, styles, scripts, comments, `&nbsp;` runs, zero-width characters, `mso-` anything) never appear as text; and no marker stays visible: a pasted run whose words would re-read as syntax (`**`, `:name:`, `[a](b)`, `^[`, a leading `- `) is kept as the words typed — which means the writer must escape them on the way out. Check tlo.ts's writer for every inline and block marker and add the escapes that are missing (read leniently, write canonically; the corpus stays byte-stable; an existing document with an unescaped marker still reads as it did). Say in docs/tlo.md what is escaped.
4. Copy stays exact (the `tlo-runs` meta; "a sentence " keeps its space); a paste of our own HTML into our own editor is unchanged by this.
5. docs/editing.md §Paste says the new rule in two sentences.

Tests: the fixture tests of 1 (node, in test/clipboard.test.ts or a file beside it); writer-escape round trips (node, src/doc tests); a browser test pasting Docs-shaped HTML into the Word Processor and seeing items with depth, and the same into a slide's words (lines) and a shape's label (line/marks-only: words only).
