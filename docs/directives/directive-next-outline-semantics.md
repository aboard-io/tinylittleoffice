## The semantics (get these exactly right; put every pure command in model.ts and unit-test it)

Terms: *item* = a row (li block or a document fence with depth); *family* = the item and everything deeper after it (`family()`); items are in document order; *visible rows* = the editor's `visible()` (inside the zoom, not under a fold).

Caret in a row:
1. **Enter at offset 0, row has words** → one empty item spliced *before* the row at the row's depth; the words (with their line attrs, children, everything) move down one index; the caret stays with the words at offset 0. ("Push the node down.")
2. **Enter at the end** → row has children showing (unfolded) → new empty first child (at+1, depth+1); otherwise (leaf or folded) → new empty sibling after the family. (As now.)
3. **Enter in the middle** → split: the words after the caret go to a new item; with children showing it is the first child, else a sibling right after the family (the kernel's `splitBlock` puts it at at+1; for a folded family or a leaf that is right; with children showing at+1 is also the first child — check the depth it gets and fix it to depth+1 there).
4. **Backspace at offset 0** (`text-exit` back):
   - row empty → remove the row (`removeAt`), caret at the end of the previous visible row (or the next, or none). As now.
   - row has words → **join with the previous item in document order** (items[i-1]): its runs appended to that item's runs (`normalRuns`), the row's block removed with `n: 1` (its children stay where they are and are now that item's or its descendants' by position), caret at the join point. If the previous item is a document card, or there is none (first item) → nothing happens. If the previous item is hidden under a fold, unfold the folds that hide it first (editor state).
5. **Delete at the end** (`text-exit` forward): join the next item in document order (items[i+1]) into this row the same way (its runs appended, its block removed n:1, caret unmoved). Next is a document card or there is none → nothing. If this row is folded, unfold it first.
6. **Delete/Backspace on an empty row that has children** → as now (`removeAt`: the family comes out a level).

Node selection (a *range*): editor state `range: { anchor: number; focus: number } | null` (block indices of visible rows). Selected rows = the visible rows from min to max in visible order; the *span* operated on = from the first selected row's block to the end of the last selected row's family (contiguous: edges live at the end of the document, assert/skip them). A selected row's whole family is selected (children, shown or hidden) — draw `.ol-row.ranged` on every visible row inside the span (a soft accent background, visible in dark mode; the contrast test guards tokens).
7. **Shift+ArrowDown / Shift+ArrowUp** from a caret: the first press selects the current row as a node (range anchor=focus=at; the DOM text selection goes; focus moves to the `.ol` tree element, which gets `tabindex="-1"` so keys and clipboard events arrive there). Each further press moves `focus` to the next visible row *after the focus row's family* (down) or the previous visible row (up); past the anchor the range flips. Also: **a tap on a row's handle (grip)** selects that row as a node (how a phone selects nodes), Shift+tap on another handle extends; Shift+click on a row's bullet likewise.
8. With a range: **Escape** or a plain **ArrowUp/ArrowDown** clears it and puts the caret in the focus row (end) / the row above or below; **Backspace/Delete** removes the span (one splice), caret into the row before (or the one after; or the ghost when nothing is left); **Tab/Shift+Tab** shifts every block in the span a level in/out (li depth ±1, fence depth attr ±1) — one splice replacing the span; Tab needs the first selected row to have a previous sibling (as `shiftFamily` requires), Shift+Tab needs the shallowest selected row deeper than the zoom base; **Alt+ArrowUp/Down** moves the span past the previous/next visible row's family (`move` op); **Mod+A** → everything (see 9); **Mod+C / Mod+X / Mod+V** → 10. Typing a letter with a range does nothing (no data lost).
9. **Select all**: `text-selectall` from a row (second Mod+A), or Mod+A with a range → range over all visible rows. Then Backspace/Delete empties the outline (the edges too? — yes: everything in the document that the span covers; a range over all rows deletes items and documents; stray edges at the end go too when everything is selected). Undo brings it back.
10. **Clipboard**: *copy* with a range → `text/plain` = the span as TLO with depths rebased so the shallowest is 0 (`write({head:{}, blocks})`, i.e. "- a\n  - b\n"), `text/html` = `docToHtml(blocks)` from src/kit/clipboard.ts (carries the generator marker so our own paste recognises it, and Write pastes a list). *Cut* = copy + remove. *Paste* (a **capturing** `paste` listener on the editor root, so it runs before the row's `<to-text>`; when you handle it, `preventDefault` + `stopPropagation`): handle when the text has more than one line, or carries our marker, or is a list in Markdown/TLO ("- ", "* ", "1. "); otherwise leave it to the row (a single line pastes as words). Pasted text → `parse(text).blocks` (HTML from elsewhere → `htmlToBlocks`) → if `readOutline(doc).loose` → `listify` → item/document blocks → rebased to the target depth; edges go to the end. Target: with a range → replace the span at the first selected row's depth; with the caret in a row → after the caret row's family at its depth (if the caret row is empty, replace it); with no rows → at the end. Afterwards the caret sits at the end of the last pasted row (or the pasted rows are the range — your call, say which). Plain multi-line text with no markers → one item per line.
11. **Contextual bar**: with a range, a `<to-context>` appears under the selected rows (anchor = a rect spanning the first and last selected row elements) with: Indent, Bring out, Move up, Move down, SEP, Copy, Cut, Paste, SEP, Numbered (pressed state), Delete. Copy/Cut/Paste buttons use `navigator.clipboard` (write: a ClipboardItem with text/plain + text/html, fallback writeText; read: readText) plus a module-level fallback so paste inside the same page works when the clipboard is refused. It hides when the range clears, follows scrolling (the kit does that).

Numbered lists:
12. The bar gets **Numbered** (lucide ListOrdered, keep:true, pressed when the chosen row is `ord`): toggles `ord` on the chosen row **and its siblings at that level under the same parent** (the list it belongs to — contiguous same-depth items between the parent's bounds), or on the top rows of the range. `readOutline` carries `ord` into Item; `itemBlock` keeps it; a row with `ord` shows its number in the bullet's place (1., 2., … counting its ordered siblings at that depth under the same parent, as `write`'s `listNumbers` does — reuse it), the line menu still opens from it. The page view (view.ts outlinePage), OPML (`text="1. …"` is wrong; OPML has no numbering — leave plain), the deck/mind/org/net hand-offs (plainTree keeps `ord`) and the text export all respect it.
13. **Text export** (.txt): bullets — `- ` for an item, `1.` `2.` for ordered ones, two spaces per depth, a document under an item as `- [App] first line`. Replace `outlineLines` (only Outline uses it) with `outlineText(v): string`. Keep `.md` (write) and `.opml`.
