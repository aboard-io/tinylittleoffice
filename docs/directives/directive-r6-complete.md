# R6-complete: type `:` and letters in any rich text and a picker of icons and emoji pops up

Read first: directive-r6-common.md, directive-r6-icons.md (built and merged before you: the emoji table src/kit/emoji-data.ts, the lazy icon set and `ensureIcons`, the chip that draws the icon), src/kit/text.ts in full (onBeforeInput's insertText path, emit, the link box pattern: `linkPop.ask(rect)`, the bubble `<to-context>`), src/kit/link-pop.ts (a manual popover placed from the visual viewport, above a phone's keyboard; how it is hidden on a tap outside), src/kit/context.ts, src/kit/icons-search.ts (searchIcons over names and tags), docs/editing.md.

Paul (2026-10-10): "Emoji/icon completion in rich text: type `:` and a character and a picker pops up with matches (icons and emoji), Enter/Tab picks, Escape dismisses; in every `<to-text>`."

Build:
1. **The trigger.** In any `<to-text>`, when the words before the caret end in `:` followed by one or more letters, digits or hyphens, with the `:` at the start of the block or after a space (so "10:30" and "re: that" never trigger), a completion opens under the caret: the best eight matches, each a row of the glyph (the icon's SVG, or the emoji character) and its name, the first one highlighted. Matching: icons by name and tag (searchIcons), emoji by name and keyword, best first (a name that starts with the typed letters before one that merely contains them; ties by name). Where the editor is `marks-only`, only emoji are offered (an icon run has no place in a drawn label unless the host already draws `ic` runs there — check Draw's and the Diagram Maker's labels and say in the report). On the first `:` the full icon set and the emoji table start loading; the starter set answers at once and the list grows when they arrive.
2. **The keys.** Up/Down move the highlight (wrapping), Enter or Tab picks the highlighted one, Escape closes it and leaves the typed `:word` as it is (and the press stops there, as the link box does), a space or a second `:` closes it (`:car:` typed in full with a known name becomes the icon — the one case where a marker is typed, so it is turned into the thing at once; an unknown name stays words), moving the caret away closes it, a tap on a row picks it. Picking replaces the typed `:word` with an `ic` run (icon) or the character (emoji) in one undoable edit, and the caret sits after it. A pick is an edit the person made: the page may scroll to the caret (see the rule the text-fixes directive wrote in text.ts's header).
3. **The popover.** The same mechanism as the link box: a manual popover, placed from the visual viewport, never clipped by a card or a scrolling host, above a phone's keyboard; `role="listbox"` with `aria-activedescendant` on the editor, rows `role="option"`, the editor's `aria-autocomplete="list"` while open; dark mode through tokens; 390px wide at most. Nothing else of the editor's behaviour changes while it is open except the keys above.
4. The editor's header documents it in one paragraph; docs/editing.md gets one row (`:` + letters → icons and emoji; Enter/Tab, Escape).

Tests (browser, real events, PW_PORT=4444): typing `:ca` opens the list with the Lucide car and 🚗 among the rows; Enter inserts the icon run and the `:ca` is gone; Tab picks too; Escape leaves `:ca`; "10:30" opens nothing; `:car:` typed in full becomes the icon; in a shape's label (marks-only) only emoji are offered and a pick inserts the character; the list sits inside the visual viewport at 390×844.
