# R6-anim: an animation placed in another document plays wherever the page can move

Read first: directive-r6-common.md, src/kit/app.ts (ViewOpts: `small`, `thumb`, `upTo`; Page), src/apps/anim/def.ts (view: `small` draws frame 0 still; otherwise animPage(anim, true), self-playing SMIL that rests where it ends), src/apps/anim/view.ts (animPage, animToSvg, frameSvg, the SMIL), src/apps/deck/view.ts (place(), the placed document at line ~169: `def.view(b.body, { small: true })`), src/apps/site/view.ts (~192, and the page script that switches pages by hash), src/apps/write/view.ts (~259, ~507), src/kit/preview.ts and src/kit/home.ts (thumbnails: `{ small: true, thumb: true }`), src/kit/shell.ts (the display and embed modes draw `def.view(this.doc)`), src/kit/exports.ts (print, PDF, PNG, HTML, `withPictures`), src/kit/pdf.ts, src/kit/raster.ts, and the deck's slideshow runtime (where a slide comes on: the `.on` class in deck/view.ts's CSS).

Paul (2026-10-10): "Animations placed on a page in the Website Builder, and in the other display formats (display link, embed, slides, exports that can move), play rather than show a still."

The mechanism: every placer asks for `{ small: true }`, and the Animator answers `small` with a still, because `small` once meant "a thumbnail". It means two things now.

Build:
1. **`still` says what cannot move.** ViewOpts gets `still?: boolean`: "drawn where nothing can move: print, a PDF, a PNG, a thumbnail" (`thumb` implies `still`; say so in its comment and make the one helper that reads opts treat it so). exports.ts passes `still: true` for print, PDF and PNG; the HTML export and the site's own export do not (a page in a browser moves). A view that places another document passes its own `still` through (`{ small: true, still: opts?.still }`): Deck, Site, Write, Outline, Board, and any other placer you find with `grep -rn "small: true"`.
2. **The Animator answers accordingly.** `view(doc, opts)`: `still` → one frame, the resting one (where a once-through ends, as animPage(…, true) rests); otherwise the playing page, repeating as the document's loop says (the way the display mode shows it on its own). A placed animation is the same SVG scaled by place(): confirm SMIL runs inside a nested `<svg>` in Chrome and WebKit (it does), and that `place()` does not strip `<animate…>`.
3. **It starts when it is seen.** On a slide that comes on in the slideshow, and on a site page shown by the hash, the placed animation starts from its beginning: the runtime calls `setCurrentTime(0)` (and `unpauseAnimations()`) on each `svg` in the section as it comes on — the SVG element's own API, no library. Slides and pages not shown are paused (`pauseAnimations()`), so a deck of ten animations does not run ten clocks.
4. **Reduced motion.** With `prefers-reduced-motion: reduce` the shell and the site page pause every animation at its resting moment (`setCurrentTime(end)` then `pauseAnimations()`), the same rule the deck's transitions follow.
5. The home rows and the Insert dialog's preview stay still (`thumb`); the Animator's own editor is untouched; the GIF and animated-SVG exports are untouched.

Tests: node tests for the Animator's view (`still` gives one frame without `<animate`, otherwise the page holds the SMIL and the loop count); a node test that Deck, Site and Write pass `still` through to a placed animation (place a tiny animation document in each; with `still` no `<animate`, without it the SMIL is there); a browser test for 3 (a two-slide deck with an animation on the second: its svg is paused until the slide comes on, then its current time is 0 and it runs).
