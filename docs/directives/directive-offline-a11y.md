# Offline mode from the hamburger, and accessibility

Paul's words: "make it possible for me to work offline with a setting in the hamburger please" and "If there are accessibility libraries that might be good."

1. **Offline.** The site is static (Vite build to dist/, served by a Cloudflare Worker, strict CSP in public/_headers, documents live in the URL so nothing needs a server once the shell is loaded; the only network uses are the short-link service tinier, Leaflet tiles, the icon chunks, fonts, and click-to-load embeds). Add a service worker (plain TypeScript built by Vite as its own entry; NOT Workbox — it is far heavier than needed) that, when the person turns the setting on, precaches the whole app: every file in the build manifest (Vite's `build.manifest` or a generated list at build time via a tiny plugin that writes `dist/offline.json` with hashed asset names), including the lazily loaded chunks (Leaflet, icons, mathjs if present, pdf chunks) and the fonts, and serves them cache-first with a network fallback; `index.html` navigation requests are served from cache so the app opens with no network. When the setting is off, the worker is unregistered and its caches deleted. The setting lives in the hamburger menu (src/app.ts shell drawer): "Keep TinyLittleOffice on this device" (or shorter, house voice) as a toggle with a line of status beneath: "Ready to work offline · 4.2 MB" / "Saving…" / "Not kept"; a new build invalidates (worker versioned by the build hash; update shows "Updated, reload"). Respect the CSP (`worker-src 'self'` may need adding to public/_headers). Do not cache map tiles or embeds. Make sure the dev server still works (register only in production builds or when `?sw` is set, your call, but tests must not register one). Update public/manifest.webmanifest if anything there is stale so the site is installable as a PWA (Paul uses iPhone Safari: check `apple-mobile-web-app-*` metas in index.html, display standalone, icons). Tests: a unit test for the precache list builder; a DOM test that the toggle writes its state and calls register/unregister (mock `navigator.serviceWorker`). Document the setting in README and the skill template if agents should know (they probably need one line: "the site works offline once kept").

2. **Accessibility.** The e2e suite already runs axe (@axe-core/playwright) in e2e/apps.spec.ts. Do a real pass: (a) extend the axe scan to every app's editor and to the one bar, the Insert ▾ menu, the templates dialog, the icon library and the hamburger drawer, in light and dark, and record what it finds in a short list; fix every finding in our code (names on icon-only buttons, contrast of the muted text and the chips, focus order after Insert, `aria-pressed` on toggles, `aria-expanded` on menus, role of the sheet grid cells, labels on sheet column-name inputs, live regions for "Saved"/"Copied" toasts, skip link to the document, focus returned after dialogs close, reduced-motion respected). Shoelace components carry their own a11y; check we pass labels through. (b) Libraries: judge, do not just add — candidates are `vitest-axe`/`axe-core` for the happy-dom tests (only if axe runs meaningfully in happy-dom; if not, say so and keep axe in e2e), `focus-trap` (only if our dialogs/popovers leak focus and Shoelace's own trap does not cover them), and nothing for colour contrast beyond a unit test (culori may be present from the other agent; if not, write a 20-line relative-luminance check). Report a short table: finding → fix, and libraries considered → decision with reason.

3. Keyboard: every app's one bar reachable by Tab with visible focus, Esc closes menus and returns focus, the Insert ▾ list is arrow-navigable. Fix what is missing.

Keep diff focused; do not restyle. Tests at each step as the pacing rules say.
