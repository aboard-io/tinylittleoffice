# R7-download: the Download menu as a table of formats, each with view, share, download and copy link

Read first: directive-r7-common.md, src/kit/exports.ts in full (kitExports, exportAs, exportItems: the download link "#/v1/<app>.<ext>/<payload>" already exists for the .pdf and an app's own formats; saveFile; the `phone()` test), src/kit/menu.ts in full (MenuItem, `<to-menu>`, `place` and its zoomed() division, the keyboard handling, the popover), src/kit/shell.ts (~945: `<to-menu class="to-download" icon-only>`, and how a ".<ext>" route is answered when a link opens: grep `view` and the export route in shell.ts and route.ts), src/kit/share.ts (shareNative, canShareNative: the share sheet, with a file where the device takes one), src/apps/anim/def.ts (the GIF export) and src/apps/deck/def.ts (PPTX), src/styles/kit.css's menu rules, test/browser/menu.test.ts and any test of the Download menu (grep `to-download`).

Paul, 2026-10-10: "Most things work with manual zoom but the download button just hovers in the left. Tighten up the download menu. It can be wider. We could use icons depending on whether we want to display in browser, bring up a share sheet, or download as a file. PDF: eye, share, download, copy (download link). GIF: eye, share, download, copy (download link)."

Build:
1. **The menu's placement under a size.** Reproduce first at size 2 (kit/zoom.ts) on 390×844: open the Download menu from the bar; its popover must sit under its button, right-aligned to it where the right edge is near, never at the page's left edge. Fix where the fault is (menu.ts `place` dividing by the wrong zoom now that the nav has its own, R7-pinch's `--to-nav-zoom`; or the popover's `left` set before the menu has a width). The fix is for every `<to-menu>`, not the Download one.
2. **A table of formats.** The Download menu becomes a grid, wider than a menu (up to 360px, the screen's width less the gutters on a phone): "Print, or save as PDF" stays the first row as it is; then one row per format (the kit's, less any the app makes its own way, then the app's own: the .pdf, the picture, the web page, Markdown, the text, a GIF, a PPTX…), the format's name at the left and four icon buttons at the right, each a 44px target with an aria-label and a title in the format's words ("View the PDF", "Share the PDF…", "Download the PDF", "Copy a link that downloads the PDF"):
   - **View** (UI.eye or Lucide's Eye): the file opened in the browser, in a new tab, from a blob URL, for every format the browser shows (pdf, png, gif, html, svg, md, tlo, txt, csv); absent (not disabled) for the ones it cannot (docx, pptx, xlsx, ics).
   - **Share** (UI.share): the share sheet with the file (shareNative with `files`); shown only where `navigator.canShare({ files })` says the device takes that file; absent elsewhere (a desktop browser mostly).
   - **Download** (UI.download): the file, as today's row did; the toast as today.
   - **Copy link** (UI.link): the link that downloads the file as it opens, as today's "Copy a link that downloads" group gave for the .pdf and the app's own; now for every format in the table (the route "#/v1/<app>.<ext>/<payload>" answers each kit format too: check what opening such a link does today and make every ext in the table do the same, a download on arrival with the document shown behind). The toast says the link is copied.
   The "Open in" hand-offs stay at the bottom as rows of their own. One mechanism: the grid is `<to-menu>` with a new item shape (a row with `actions: [{ icon, label, does }]`) rather than a second menu element; a row without actions is a plain item as before.
3. **Keys and reading.** The grid is one `role="menu"`: Up and Down move between rows, Left and Right between a row's actions (the row's first action is the focus when the row is reached), Enter and Space act, Escape closes, Home and End; each action is a `menuitem` with its label; a screen reader hears the format's name then the action. Touch targets never overlap at size 2 with the nav at its limit; the grid scrolls inside the popover where the screen is short.
4. Strings through t(); the new ones in en.ts (and, since the nine languages exist, each language file gets them in the same voice, through `npm run i18n:gaps -- <code>`: a missing key fails i18n:check). docs/editing.md names the menu's keys.

Tests (browser, 390×844, failing before): the placement at size 2; the Word Processor's Download menu lists the rows and, for the .pdf, four actions (share only where canShare is stubbed true); View opens a blob URL in a new tab (stub window.open and assert the blob's type); Share calls navigator.share with a File of the right type (stub); Copy link puts "#/v1/write.pdf/…" on the clipboard and opening it downloads (the existing test, extended to .png and .md); the keys of point 3; i18n:check green with every language.
