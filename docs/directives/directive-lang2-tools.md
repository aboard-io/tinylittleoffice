# Languages, round two: the tools for nine more scripts

Nine languages join the nine of 2026-10-10 (es, fr, de, pt-br, it, nl, ja, zh-hans, ar): **Russian (ru), Ukrainian (uk), Polish (pl), Bengali (bn), Hindi (hi), Urdu (ur), Haitian Creole (ht), Korean (ko) and Traditional Chinese (zh-hant)**. Paul, 2026-10-11: *"make sure the major languages of NYC are addressed and colloquially appropriate for the communities here"*, and *"Ukrainian too please"*. These are New York's designated citywide languages (Local Law 30) with Hindi and Traditional Chinese, the script of the city's Cantonese- and Taiwanese-speaking communities, added.

Before the translators start, make the tree ready for them, in one branch:

1. **Each code is a language the site knows**: the language files are found by `import.meta.glob` (kit/i18n.ts), so a new file is enough to be listed; check that the picker (the drawer's head) orders and names the nine natively (`Русский`, `Українська`, `Polski`, `বাংলা`, `हिन्दी`, `اردو`, `Kreyòl ayisyen`, `한국어`, `繁體中文`), that `browserLanguage` maps `zh-TW`, `zh-HK` and `zh-Hant-*` to `zh-hant` and `zh-CN`/`zh-SG`/`zh-Hans-*` to `zh-hans`, and `ur`, `hi`, `bn`, `ht`, `ko`, `ru`, `uk`, `pl` to themselves; a node test for the mapping.
2. **Right to left**: `RTL` in kit/i18n.ts already names `ur`; the browser test of round one (languages.test.ts: `lang` and `dir` on `<html>` follow the choice) runs for every file, so it will cover Urdu once the file exists; make sure the stylesheet's logical properties hold for a second RTL language (the Arabic round's findings in docs/translation.md apply).
3. **Plurals**: `Intl.PluralRules` gives ru, uk and pl `one`, `few`, `many`, `other`; the extractor (`scripts/i18n-extract.ts`) already reads the categories from Intl and `i18n:gaps` writes the plural forms a language needs; confirm with a node test that a `{n|one|few|many|other}` string renders for 1, 2, 5 and 21 in Russian, Ukrainian and Polish, and that Bengali, Hindi and Urdu (`one`, `other`), Korean and both Chinese (`other` only), Haitian Creole (`one`, `other`) each render.
4. **The glossary lint** (test/glossary.ts): words are matched by stem where spaced, by character pair in Chinese and Japanese, by root in Arabic. Urdu is an Arabic-script language with Persian/Hindustani words: use the Arabic root matcher for Arabic-derived words and the stem matcher otherwise (a word that fails both is reported, as now); Korean takes a stem of the first syllable block or two (particles come off the end); Bengali and Hindi (Devanagari and Bengali scripts, spaced) take the stem matcher with their combining marks kept with their base; Traditional Chinese the character-pair matcher. A test per script with two words that should match and one that should not.
5. **Fonts for the measuring tests**: `test/browser/label-widths.test.ts` measures every label in its slot's font; the box has no Bengali, Devanagari, Hangul, Nastaliq or Traditional Chinese fonts, so a label would measure as fallback boxes. Install `fonts-noto-core`, `fonts-noto-cjk` and `fonts-noto-extra` on the box (`sudo apt-get install -y …`, or say in the report that it needs doing by hand), and in the test map each language to the font family the box draws it with, so a width is a width. The export's fallback metrics (`test/browser/metrics.test.ts`, round twelve) gain the same scripts, within the 10% rule, or the report says which scripts the exports cannot yet measure.
6. **The product name** key `'Tiny Little Office'` and the `'{app} Templates'`, `'Templates for {app}'` keys are translated like any other; nothing special.
7. docs/translation.md gains a section for these nine: what is particular to each (Urdu right to left, Nastaliq where the device has it; Haitian Creole's orthography (the official 1979 one, `Kreyòl`, no French spellings); Traditional Chinese is not a conversion of the Simplified file but its own translation in the Hong Kong and Taiwan usage of NYC's communities; Ukrainian never a transliteration of the Russian).

Tests: the node tests above; `npx vitest run` whole; `npm run build` (the new languages are lazy chunks; the report says their sizes once they exist, which is the translators' round).
