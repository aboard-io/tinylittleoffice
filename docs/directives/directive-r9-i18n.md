# R9-i18n: translations measured by machine

Read first: directive-r9-common.md, scripts/i18n-extract.ts (check, gaps, the SAME set), src/kit/i18n.ts, src/i18n/en.ts's header (the length rule), test/i18n-languages.test.ts and test/browser/languages.test.ts (the 390px checks and what they found), src/kit/commands.ts (R9-commands: each command knows where it is drawn), the translators' reports in docs/directives (the `tooLong` and `ambiguous` notes of round "languages": grep the journal's summary in docs/directives/README.md if kept, else the nine commit messages), the nine language files.

Why: the checks are good at shape (keys, placeholders, plurals); the failures found were length and glossary drift, found by rendering screens and by eye.

Build:
1. **Width by metrics, at check time.** A browser test (it needs the fonts) that, for each language and each command in a bar or a menu (the registry says where), measures the translated label with the slot's font and compares it to the slot's room: a bar button's label budget is the English label's width × 1.33 (the one-third rule) or the bar's own max label width, whichever the stylesheet says; a dialog button's budget is the English width; a menu row's is the menu's width less the icon and the keys. The failure names the key, the language, the measured and the allowed widths, and the test is the source of the length rule from now on (en.ts's two sentences point to it). What fails today is listed in the report; the builder shortens where a shorter word with the meaning exists (the translators' notes say where it does not) and otherwise raises the rule for that slot with a reason in the test.
2. **Glossary drift.** A node lint: for each language, the product's terms (document, link, short link, Display Link, template, card, slide, sheet, cell, row, column, page, bar, Share, Download, Undo, Redo, Keep, Kept, Forget, Private, Saved, password, sign, key, Present, Insert, Look, paper, …, the list in the test) found in English keys are mapped to the words used for them in the translated values (by alignment on the keys that are one term long, then looked for in the longer ones); a term translated two ways is a failure naming both, unless listed with a reason. The nine translators' glossaries (in the commit messages) are the first allowlist.
3. **A translation memory for the extractor.** When an English key changes by a few words, `i18n:gaps` offers the old translation as a draft under the new key (fuzzy match on the English, by token overlap above a threshold), marked `// draft from "<old key>"` so a translator or the check finds it; `i18n:check` fails on a draft marker left in, as it does on "sort me". Never applied automatically to a language file; only offered.
4. **The same-as-English warnings become a decision**: the SAME set is per language and per key (a comment in the file is enough: `// same`), and a warning not decided is a failure, so the list stops growing silently.

Tests: the width test, per language; the glossary lint; the memory's matcher as a node test with cases; i18n:check's new failures.
