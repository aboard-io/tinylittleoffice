# R8-exports: every format is one object

Read first: directive-r8-common.md, src/kit/exports.ts in full (kitExports with its empty `build` placeholders, exportAs and its five special cases, STILL, the `shows`/view-type helper ~235, the Download table's items ~287, saveFile, printPages, pdfOf, picture, htmlOf, withPictures), src/kit/app.ts (Export, ExportContext, Handoff, ViewOpts), src/kit/menu.ts (MenuItem with `actions`, MenuAction), src/kit/share.ts (shareNative with files), src/kit/shell.ts (how a ".<ext>" route downloads on arrival; the Download menu's mounting), every app's `exports` in src/apps/*/def.ts (deck's PPTX, anim's GIF, write's DOCX and HTML, sheet's XLSX and CSV, cal's ICS, any other), test/browser/download.test.ts or wherever round seven's Download table tests live (grep `to-download`), test/exports.test.ts if any.

Why: the kit's five formats are special cases inside exportAs, with placeholder builders returning empty bytes so they can sit in a list, and a second place decides which the browser can show and a third which get a link. The Download table wants each format to say what it is.

Build:
1. **One shape.** In app.ts, `Export` becomes: `ext`, `mime`, `label()`, `shows: 'own' | 'text' | null` (the browser shows the file as itself, as plain text, or not at all), `still?: boolean` (drawn with ViewOpts.still: a PDF, a PNG), and `build(doc, ctx): bytes | string | Promise<…>` that is real for every format. `ctx` gains what the kit's formats need to build without the shell: the app's def (for `view`), the title, the link. The kit's formats (pdf, png, html, md, tlo) are five such objects in exports.ts, each building its own bytes through the pages (pdfOf, picture, htmlOf) with STILL where it says `still`. An app's own formats are the same shape; where an app overrides a kit format (write's HTML), its object wins by `ext`.
2. **One list, one path.** `formatsOf(def)` is the kit's formats less the app's overrides, then the app's own: the Download table, the ".<ext>" route, `exportAs` and the share sheet all read it. `exportAs(ext, current)` is: find the format, build, hand over (saveFile), nothing else; print is not a format but the table's first row as today, calling printPages. Nothing in exports.ts switches on an extension any more (a node test greps for `ext ===` and fails on one outside tests).
3. **The table reads the shape.** View is shown where `shows` is not null (as its own type, or as text), Share where the device takes the file, Download always, Copy link always; the row's words are the format's label; the hand-offs stay below. The round-seven tests pass; add one that every format in `formatsOf` for every app builds for its blank document to bytes of the right mime (a node test where the build needs no browser; a browser test for the drawn ones).
4. **The route.** "#/v1/<app>.<ext>/<payload>" downloads for every ext in `formatsOf(def)` and shows the document behind; an unknown ext opens the document plainly (no error page). Covered by a test for one kit and one app format.
5. Headers in the house voice; docs/kernel.md's export paragraph updated if it names the old path.

Tests: the node grep; the build-every-format test; the table at 390×844 for Write (pdf, png, html, md, tlo, docx) and Animator (gif) with the right actions present and absent; the route test; the existing download tests.
