# R5-A: a money column names its currency

Read first: directive-r4-common.md (the contract), docs/tlo.md (tables, the column `name:type` syntax), src/doc/model.ts (Column, ColType), src/doc/tlo.ts (COL_TYPES, the column head parser around line 695, columnText), src/doc/formula.ts (formatCell line ~550, and the money read at ~284), src/apps/sheet/editor.ts (the column type menu, the Option type's per-column form is the pattern for a type with a setting), src/apps/write/table.ts and model.ts (money(), the `currency` attribute from the head), src/apps/site/model.ts and forms.ts (the shop's `currency:` head and askShop), src/apps/site/templates.ts (the plumber's price table shows "$" beside a British firm; the cottage table is a number column with "(£)" in its name), the sheet, write and site tests, test/doc/corpus.

Paul (2026-10-10), answering the builders' note that money columns always show "$": the fix is a currency per column; he approved it.

Build:
1. Model: `Column` gets `currency?: string`. In the column head, `Price:money(£)` and `Price:money(GBP)`: the parentheses after `money` hold a symbol (one to three characters, not letters) or an ISO 4217 code (three capital letters); `Price:money` alone stays as it is. Read leniently (spaces inside the parentheses, lower-case codes), write canonically (`money(GBP)`), byte-stable through the corpus. Only `money` takes it; another type with parentheses is read as a plain text name.
2. Formatting: `formatCell(v, type, currency?)`: a symbol is written where "$" is today (`-£1,234.50`); a code goes through `Intl.NumberFormat(undefined, { style: 'currency', currency })` (so GBP shows as £ to a British reader and as £ or "GBP" elsewhere, as the browser decides; the negative sign and two decimals as the browser decides too). When the column names none: the document head's `currency:` where the app has one (Word Processor, Website Builder) else "$", as today. Reading a typed value in a money column strips a leading or trailing symbol or code and the grouping commas, so "£1,200" or "1200 GBP" typed into the cell is 1200.
3. Interface: in the Spreadsheet's column type menu, Money gets a small form on pick (and on re-pick) with one field, Currency, placeholder "$", a datalist of the common ones ($, £, €, ¥, ₹, USD, EUR, GBP, JPY, INR, CNY, BRL, CAD, AUD, CHF); empty keeps the default. The Word Processor's table (to-write-table) and the Website Builder's shop table (edited in the Spreadsheet dialog) get it through the same shared code: put the form in src/kit if both need it, else beside the column menu. The head `currency:` of the Word Processor and the Website Builder stays as the default for columns that name none; the site's shop form keeps its Currency field.
4. Templates: the plumber's price table becomes `Price:money(£)`; the cottage's "(£)" number column becomes `money(£)` with the suffix taken off the name; look through every app's templates for a number column standing in for money because of a currency, and fix each (grep for "£", "€", "₹", "R$" in column names and blurbs). Exports (CSV/XLSX/DOCX/HTML/PDF pages) show the formatted value as the app shows it.
5. docs/tlo.md: one sentence in the tables paragraph.

Tests: parse/write of the column head (symbol, code, lenient forms, non-money with parentheses); formatCell with a symbol, a code, none, negative; reading typed money with a symbol/code; a DOM test of the Spreadsheet's Money form writing `money(GBP)` into the head and the cells showing it; a Write table test that a column currency beats the head's; the site plumber template's price shows £.
