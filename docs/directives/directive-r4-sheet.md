# R4-G: the Spreadsheet, and the kit's menu keys

Read first: directive-r4-common.md, src/apps/sheet/{model,editor,view,style.css}.ts and tests, e2e/sheet-phone.spec.ts, src/doc/table.ts (columns: name, type), src/kit/{menu,insert,text,chart}.ts, test/browser/menu.test.ts, docs/editing.md §4.

Paul: "The number column of the spreadsheet should always be as small as possible on the left. It's super wide now. It's not a real column; neither is the top row a real row. It's interface. The Rich Text columns in the spreadsheet are not supposed to be markdown. That is bad. Don't make me wait until a column is empty to remove it. The checkbox column should be big and thick empty box or full box, right now it's anemic or blank. Add an Option type column which takes what's been entered and turns it into a dropdown à la Excel, so that I can type BAD, OKAY, GOOD and the next column pops up GOOD when I type G but ALSO lets me type GREAT. Menu options only half respond to cursor keys, they come and go depending on random key combos. Put the chart ABOVE the table when it's inserted."

1. **Row numbers and the column heads are interface, not cells**: the row-number gutter is as narrow as its widest number plus 8px (a `ch`-based width from the row count), muted type, no cell background or borders, right-aligned; the head row is as short as its names need (32px on a mouse; the 44px coarse-pointer rule stays for the finger but with the same quiet look); neither is drawn like a cell. The corner is empty. Keep the sticky behaviour and the menus they open.
2. **Rich columns are rich, not Markdown**: a cell of a `rich` column is edited with `<to-text shape=line>` (the bubble for bold, italic, underline, strike, highlight, link), stored as the kernel's inline form by the code (never typed by a person), drawn rich in the grid and the page. Arrows, Tab, Enter, Escape and the formula strip still behave as §4 says in such a cell (the strip shows the plain words, read-only, or the rich box; your call, say which). The typing burst undo key stays per cell.
3. **Remove any column**: the column menu's Remove works whatever the column holds (undoable, one op; references that pointed into it become #REF as a spreadsheet does, or are left as written: say which) and never below one column; the "+" and the three-column default stay.
4. **Checkbox column**: a 24px box with a 2px border in the ink colour, empty, or filled with a thick check in the accent; a 44px tap target on the cell; Space toggles; the written value stays as it is.
5. **Option column type** (`option` in the column's type, written as the kernel writes types): the cell is an `<input list=…>` with a per-column `<datalist>` of the distinct values the column already holds (plus the value being typed); the browser offers "GOOD" on "G" and still takes "GREAT"; a small caret at the cell's right opens the list (focus + `showPicker()` where supported); the column menu offers the type beside the others; a template shows it (a status column in the project tracker, say). Byte-stable; the page view draws the words.
6. **Menu keys (kit/menu.ts)**: find why arrows "come and go": make every `<to-menu>`, `<to-insert>` and the templates listbox a proper roving-focus menu: ArrowDown/Up move (wrapping), Home/End, type-ahead by first letters, Enter/Space choose, Escape closes to the opener, Tab closes; modifiers never change the meaning; focus lands on the first item when opened by keyboard and on the menu itself when opened by pointer. A DOM test presses the keys in sequence, with and without stray modifiers, and asserts the focused item each time.
7. **Chart above the table**: the chart block inserted by Insert ▾ (and its picker) goes before the table, not after; the view and exports draw it there; an existing chart below stays where it is.
