The kit now has `<to-context>` (src/kit/context.ts): a small toolbar popover placed centred under an anchor (an element, or a function returning a DOMRect) with items `{label, icon|swatch|text, pressed, disabled, keys, does}` and `SEP`; its buttons never take the focus; `show(anchor)`, `hide()`, `refresh()`, `isOpen`. Use it; do not build another popover.

## What to build

1. **Words edited on the shape, not in a box.** Remove `.draw-label-pop` and the `<input>`. Editing a shape's words (double tap, Enter, the T tool placing a text shape, "Edit the words" in the context bar) puts an HTML overlay `<div class="draw-words" contenteditable="plaintext-only">` (fall back to `contenteditable="true"` + stripping on input where plaintext-only is unsupported) exactly over the shape's words: the `.draw-wrap` gets a positioned inner element the size of the SVG; the overlay sits at the shape's text box in CSS pixels (scale = svg rect width / W), same font family (`var(--to-font)`), `font-size: TEXT_PX[z] * scale`, line-height 1.25, text-align centre (left for kind `t`), colour the shape's ink, transparent background, no border, a thin accent outline so it reads as editable, `min-width` the shape's inner width; while editing, the SVG draws that shape with empty words (so layout is unchanged and nothing doubles); `" | "` in the model is a line break in the overlay and back (`innerText` ↔ `' | '.join`); an icon prefix (`:rocket `) is kept out of the overlay and re-attached on save. Every `input` event patches the shape's text (`patchShape`, key `label:<i>`) so the picture follows live. Enter commits and closes; Shift+Enter is a line break; Escape restores the words from when editing began (one undo entry) and closes; blur commits. For kind `t`, the box grows with the words (measure the overlay's scrollWidth/Height; patch w/h when larger; never below the default). A newly placed text shape starts editing at once with its placeholder words selected (typing replaces them). **iOS:** `focus()` must run synchronously inside the tap/keydown handler that opens editing (not after `updateComplete`), so render the overlay always (hidden) and open it imperatively: set its text, unhide, position, focus, select. Lit must not re-render the overlay's text while editing (keep its content out of the template; set it imperatively).
2. **The contextual bar.** A shape selected (and not mid-drag) → `<to-context>` shows under the shape's bounds (`bounds(s, shapes)` → CSS rect via the svg's rect) with: the six inks as swatches | fill/line style (No fill/Grey/Solid or Solid/Dashed/Dotted, as `styleItems` has them) | text size S M L XL as letters (for shapes that can have words; pressed = current) | Edit the words (Tag icon; Enter), Duplicate (Mod+D), Bring to front, Send to back | Copy, Cut, Paste | Delete. While words are being edited, the bar anchors to the overlay and holds **text size and colour** only ("right below the text"). It hides while dragging/resizing and on deselect; refresh after a move; the kit follows scrolling. The main bar loses the Colour and Style menus (now contextual) and keeps Arrange (which keeps Delete); Insert ▾ unchanged. Keep "Label…" out: the words are edited in place.
3. **Copy, cut, paste, delete.** `copy`/`cut`/`paste` listeners on `.draw-wrap` (it has the focus after a tap; Mod+C/X/V keydowns are not prevented so the native events fire). Copy with a shape selected → `text/plain` = a complete TLO drawing (the table header and the row(s), via the model's `shapeCells` and the kernel's `write`) so it pastes into another drawing, into Motion, or into Write/Sheet as a table; `text/html` = the kit's `docToHtml` of that table block (carries the generator marker). Cut = copy + remove. Paste: parse the text → the first table with a Kind column → `tableShapes` → added as rows (one `rows` op), placed one grid step down-right of where they were (so a paste over the copy is visible), joins (k/j) between pasted shapes renumbered to the new rows, joins to shapes not pasted dropped; the pasted shape is selected (the last, or the first — say which). Paste of a plain line of words → a text shape with those words in the middle. The context-bar Copy/Cut/Paste use `navigator.clipboard` (write: ClipboardItem text/plain + text/html, fallback writeText; read: readText) plus a module-level clipboard fallback so paste within the page works when the clipboard is refused. Multi-select is not asked for; one shape at a time is fine, but write the copy/paste code over `Shape[]` so it extends.
   Delete: the Delete/Backspace keys must remove the selected shape when the wrap has the focus after a tap — verify this in a DOM test with real pointer events then a keydown (it looked right in code; prove it), and the context bar's Delete does the same on a phone.
4. **Pixel mode**: unchanged, except the context bar does not appear there.
