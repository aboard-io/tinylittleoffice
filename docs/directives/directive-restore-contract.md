# RS-2: the contract that works

Rows: docs/gap-analysis.md "Contract". Depends on RS-1 (signing in the kit) having landed on next; if `src/kit/sign.ts` is absent when you start, stop and report. Old tree: src/apps/contract.def.ts (parseContract, serializeContract, signedMessage, keyMark) and its tests; new tree: src/apps/write/{editor,model,view,templates}.ts (the Contract template with its signatures fence), src/kit/doc-dialog.ts, src/kit/sign.ts.

Build: the signatures fence of a contract is a table of Name | Key | Signature | Signed (date); its card in the editor shows each row with its state (valid, with the key mark and the date; mismatch in red; unsigned); a **Sign this contract** action on the card signs the contract's text (everything above the fence, as the old signed message defined it; port it exactly so old contracts verify) with the device's key and adds or updates the signer's row with their name (from the envelope's `by`); every row verifies on open and after each change (a change after signing marks every signature stale until re-signed: the contract's words are what was signed). The printed page and the PDF/HTML/docx exports draw a signature block (name, date, the key's short mark, "verified" or not at the time of printing). A second signer opens the same link and signs: both rows verify. Tests: node for parse/serialize/message (old-tree fixtures), DOM for the card states, Sign, stale, two signers, the printed block.
