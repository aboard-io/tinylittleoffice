# R4-A: names, Link / Display Link, home rows, hamburger, bar labels, viewport

Read first: directive-r4-common.md, src/kit/{shell,home,drawer,library,route,share,links,short,bar,menu}.ts, index.html, public/manifest (if any), README.md, test/browser/{shell,drawer}.test.ts, e2e/smoke.spec.ts.

1. **"Tiny Little Office"** everywhere people read it: the header, `<title>`s, the home h1, the manifest name, OG/share text, the About text, exports' generator name where shown to people (the clipboard MARKER constant may stay), README and docs. Grep "TinyLittleOffice" and account for every hit.
2. **Document names.** A new document (opened blank from the home page, the hamburger, or "New …") gets a title at once: `New {App} {YYYY-MM-DD} #{n}` ("New Spreadsheet 2026-10-09 #1"), the date local, n the first number not used by a document of that app with that date prefix in the device's library (src/kit/library.ts; under Private the library is empty, so #1). The title goes in the head (`retitle`) when the first change is made (a blank page left untouched writes nothing), so the tab title, the kept entry and the downloads carry it; the title box is prefilled with it and selected when the person edits it. Replace the "Untitled {noun}" placeholder path with this where a document is new; keep "Untitled {noun}" only for a document that arrives with no title (an old link).
3. **Link and Display Link.** The Share dialog (shell.ts ~240) offers **Link** (the editing link, as "Copy link" did, now named "Link") and **Display Link**: the same document opened in display mode. Display mode is a route flag (`route.ts`: `…#/v1/<app>/<payload>?d` or equivalent; never inside the shared payload) under which the shell shows the app's `view(doc)` pages full width, one under another, readable and printable, with no bar and no editor, a small top line with the title and an **Edit** button that drops the flag and opens the editor. Short links carry the flag too. The QR offers the same two. Tests: the route round-trips the flag; display mode renders pages and no editor; Edit returns.
4. **Home page as rows, not cards.** Each app is one row of the full width (icon, name, the templates button at the right), the documents listed beneath it indented; the same on desktop as on a phone (no grid, no card borders; a thin rule between rows). Keep the 44px rows, the hidden h1, the Drive rows, the "n more".
5. **Hamburger.** The search placeholder is "Find app, template, or doc" when the library holds documents, else "Find app, template". It matches apps, templates (by name and app) and kept documents (by title), listing them under small headings; Enter opens the first. Below the search the apps are rows like the home page's, each with the templates button (reuse `<to-templates>`), so a template is reachable from inside any app.
6. **Bar labels never wrap.** `to-bar` buttons get `white-space: nowrap`; "Short link (expires)" and any label longer than two words is shortened in its string (the expiry goes in the hint/tooltip, not the label). Grep the bars' btn() labels across src/apps and src/kit for long ones and shorten them; list the changes.
7. **Viewport meta**: drop `interactive-widget=resizes-content` from index.html (it warns in Safari and Firefox); keep the visual-viewport handling.

Tests: shell (names, new-document title and numbering through the library, Link/Display Link, display mode), drawer (placeholder by library state, the three kinds of result, templates rows), home rows at 1100 and 390 (nothing wider, rows identical in shape). Update e2e/smoke.spec.ts for the new name and run it with PW_PORT=4400.
